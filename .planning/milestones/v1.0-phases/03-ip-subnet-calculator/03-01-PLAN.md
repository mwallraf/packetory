## Phase Goal (MVP user story — derived from ROADMAP Goal + Success Criteria)

**As a** network engineer, **I want to** enter an IPv4 or IPv6 CIDR and instantly see its full, mathematically-correct subnet breakdown with every field copyable and the result reflected in a shareable URL, **so that** I can get my subnet answer in seconds and hand a teammate a link that reproduces it exactly.

This plan delivers the first vertical slice of that story: a working IPv4 breakdown with URL state.

## MVP Slice — what a user can do after this plan

Before: `/tools/subnet` is a `planned` registry entry with no page. After: a user loads `/tools/subnet`, sees `192.168.1.0/24` already broken into network / broadcast / first & last host / host count / mask / wildcard / binary, copies any field, types a new IPv4 CIDR (getting inline validation on bad input), and shares the URL so a fresh tab reproduces the result. (IPv4 reverse-DNS, IPv6, subdivisions, and SEO arrive in later plans.)

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL `?cidr=` -> client render | User-controlled query string is read on mount and reflected into page text and into window.history.replaceState |
| User keystrokes -> parse -> render | Untrusted CIDR strings enter the pure BigInt parser |
| (no server tier) | All computation is client-side BigInt math; no server request handles the CIDR (RESEARCH Architectural Responsibility Map) |

| T-03-01 | Tampering / EoP | `?cidr=` value rendered into SubnetTool | high | mitigate | Render the value only as React text content (default JSX escaping); never `dangerouslySetInnerHTML` for user input; the History API write only ever sets an `encodeURIComponent`-escaped URL, never innerHTML. Canon XSS is covered by /gsd-secure-phase + React escaping — not minted as a bespoke prohibition. |
