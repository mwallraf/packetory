<objective>
Complete the QUAL-08 error-state matrix and record-type display completeness for the DNS tool. Turn the
walking skeleton's minimal generic failure fallback into five clearly-distinguished, inline states —
invalid-input, NXDOMAIN, empty-NOERROR, rate-limited, resolver-unavailable — each with its own icon,
short label, one-line explanation, and (for the two genuine-failure states) an inline Try-again button.
Harden and prove DNS-04 race-safety end-to-end.

Purpose: DNS is the phase the roadmap chose to establish "the richest error-state matrix" (QUAL-08 lives
here for exactly this reason). Getting NXDOMAIN vs empty-NOERROR spelled out in plain language (D-05),
and rate-limited vs resolver-unavailable told apart (Pitfall 6), is the core deliverable of this plan.

Output: the full error-state rendering + classification in DnsTool.tsx, a component test covering all 5
states + loading/skeleton, and E2E coverage for the error states + the out-of-order race guarantee.

Depends on 04-01: this plan modifies `DnsTool.tsx` (the classifyError branch + the five state components)
and extends `tests/e2e/dns-lookup.spec.ts`; both are 04-01 artifacts, so this is Wave 2.
</objective>
