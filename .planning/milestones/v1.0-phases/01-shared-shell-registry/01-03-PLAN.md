<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client request headers -> app/api/ip route | `x-forwarded-for` is client-influenceable; only the platform-set portion is trustworthy. |
| server IP value -> rendered DOM | The IP string is reflected into the page and the clipboard. |
| visitor IP -> analytics/logs | The IP is PII; it must not leak into telemetry. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Spoofing | x-forwarded-for parsing | high | mitigate | parseForwardedIp selects the platform-trusted client entry (not the attacker-appendable last entry) and validates the candidate against a plausible IPv4/IPv6 shape; the value is display-only and never used for any security/access decision. |
| T-03-02 | Tampering / Injection | IP value rendered into DOM | medium | mitigate | The value is validated as an IP literal before rendering and is emitted through React's default text escaping (no dangerouslySetInnerHTML), so a crafted header cannot inject markup. |
| T-03-03 | Information Disclosure | visitor IP handling | medium | mitigate | The IP is ephemeral display-only: not logged server-side, not sent to analytics, not persisted (enforced by the privacy prohibition); route sets no-store. |
</threat_model>
