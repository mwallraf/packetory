<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser DOM events -> global keyboard hook | Global keydown listener processes untrusted user key events on every page. |
| current URL/path -> active-link logic | The pathname (user-controllable via navigation) drives which nav link is marked active. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | useKeyboardShortcut global listener | low | mitigate | The hook dispatches only to a fixed, closed set of known shortcut keys ({slash,enter,escape,copy}); it never `eval`s or reflects key data, and the copy branch is gated to non-editable focus so it cannot intercept text-field input. |
| T-02-02 | Denial of Service | active-link path parsing | low | accept | Active-link matching is a pure string compare against registry slugs with no regex backtracking or network call; a crafted path at worst matches zero links (safe default). |
| T-02-03 | Elevation of Privilege | registry-derived nav | low | accept | Nav is rendered from a static, compile-time-typed registry with no user-authored content, so no injection path exists into the nav list. |
</threat_model>
