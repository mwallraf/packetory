## Color

60/30/10 split — inherited from Phase 1, unchanged this phase (both light and dark themes, values confirmed live in `app/globals.css`):

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` | `#020617` (slate-950) | Page background |
| Secondary (30%) | `#F1F5F9` (slate-100) | `#0F172A` (slate-900) | Cards, nav bar, footer |
| Accent (10%) | `#0891B2` (cyan-600) | `#22D3EE` (cyan-400) | See reserved list below (one row added this phase) |
| Destructive | `#DC2626` (red-600) | `#EF4444` (red-500) | Reserved for destructive actions only — none in this phase |

Accent reserved for (explicit list — never "all interactive elements"):
- Copy-button icon default/hover/active state (IP widget) — Phase 1
- Copy-confirmation checkmark/"Copied!" flash — Phase 1
- Active/current nav-link indicator — Phase 1
- Keyboard focus ring (all interactive elements) — Phase 1
- "Featured" tool-card accent border/badge tint — Phase 1
- Theme-toggle icon — Phase 1
- **NEW (Phase 6): Full-card hover and focus-visible ring on `status !== "planned"` tool cards** — the entire `Card` boundary tints/rings with the accent (`--ring` / `--primary` token), reinforcing "this whole card is the click target." Applies ONLY to navigable cards; `status: "planned"` cards get zero accent treatment (D-05).

**Prescriptive implementation (Claude's discretion resolved):**
- Default `Card` ring stays `ring-1 ring-foreground/10` (existing neutral border, unchanged).
- Hover (mouse, `status !== "planned"` only): `has-[:hover]:ring-primary/40 has-[:hover]:shadow-md transition-shadow` on the `Card` container — subtle accent tint + lift, not the full 3px focus treatment.
- Focus-visible (keyboard, `status !== "planned"` only): `has-[:focus-visible]:outline-none has-[:focus-visible]:ring-[3px] has-[:focus-visible]:ring-ring/50` on the `Card` container — matches the exact width/color/opacity convention already used in `SiteHeader.tsx`'s logo/nav-link focus ring (D-04).
- `status: "planned"` cards: no `has-[:hover]`/`has-[:focus-visible]` classes at all — they have no focusable/hoverable descendant to trigger them anyway (D-06), so this falls out naturally from D-01/D-06 rather than needing a separate override.

Everything else (card borders at rest, muted "Coming soon" badge, body/description text, category label) stays neutral slate — unchanged.
