  <how-to-verify>
    1. Start the dev server: `npm run dev`, then open http://localhost:3000.
    2. Mouse-hover any active tool card (e.g. "UUID Generator"): confirm a subtle accent ring plus a shadow lift appears around the ENTIRE card boundary — not just around the title text.
    3. Press Tab repeatedly: confirm each active card receives a visible ~3px accent focus ring that visually encloses the whole card; press Enter on a focused card and confirm it navigates to that tool's `/tools/{slug}` page.
    4. Confirm the ring geometrically wraps the full card for both a plain active card and a featured card (featured cards carry an accent tint at rest but must still show the same full-card focus/hover ring).
    5. Open DevTools device toolbar, set the viewport to 320px wide (single-column layout): repeat the hover pass and the Tab pass and confirm the ring still wraps the full card with no clipping and no horizontal scroll.
    6. Planned-state check: the live registry currently has no `status: "planned"` tool, so confirm the planned-inert case via the automated proof instead — `npm test -- ToolCard` (from plan 06-01) asserts a planned card renders no anchor and no `has-[:hover]`/`has-[:focus-visible]` classes, i.e. no ring. Note in your resume message that planned-state was verified via that unit test rather than visually.
  </how-to-verify>
  <resume-signal>Type "approved" if the ring encloses the full card at both breakpoints (and planned shows no ring per the unit test), or describe the visual issue to fix.</resume-signal>
