Deliver PWD-04 in a framework-agnostic `lib/password`: every generated password contains at least one character from each enabled set, and the distribution stays unbiased because the whole password is resampled until it qualifies. This plan creates the contracts every later plan builds on (types, constants, errors), the one audited CSPRNG primitive `randomInt` (D-01, D-02), the alphabet and option-normalization trust boundary (D-06..D-09), and `generatePassword` (D-03, D-04). It also adds the deterministic fill helpers that this phase and the Phase 13-14 UI tests use.

Purpose: Phase 13 only wires and renders. The correctness guarantee behind PWD-04 (ROADMAP Phase 12 SC-1) must exist and be proven first.
Output: 7 source modules under `lib/password/` plus `generate.test.ts` and `charset.test.ts`. No page, route, registry entry or UI.

Requirement note: PWD-04 is the only requirement ID Phase 12 owns. This plan delivers it directly. The library guarantees behind PWD-07, POUT-03, PHR-01..03 and STR-01..04 are built in plans 12-02..12-05 and claimed by Phases 13-14.
</objective>
