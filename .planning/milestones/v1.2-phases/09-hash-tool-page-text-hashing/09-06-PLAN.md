<objective>
Shareable input without leaking it: `/tools/hash?text=…` restores its text on load (with pending rows, never the sample's digests), the address bar is never written while typing, and an explicit, absolute, 2,000-character-capped "Copy link" is the only way text gets into a URL. A redact regression test proves `text` never reaches analytics.

Purpose: TEXT-04. Tracer-first: Task 1 proves URL -> textarea -> worker -> digests end to end; Task 2 adds the capped Copy link; Task 3 closes the privacy loop with the analytics regression and a real-browser link round trip.
Output: HashTool URL read + pending state, `lib/hash/share-link.ts` (+ tests), Copy link UI, redact regression, RTL and e2e suites.
</objective>

## Decisions recorded in this plan

- Copy link is absolute (`window.location.origin` + path), per autonomous decision 4 / UI-SPEC Flag 4, so pasted links work on any origin including preview deployments.
- Copy link is disabled for empty text: an empty `?text=` loads the sample (edge TEXT-04 empty), so a link for empty input would not reproduce the state.
- The 2,000 cap is inclusive: an encoded length of exactly 2,000 is allowed; 2,001 is not.
