## Page Structure (top to bottom)

Server shell `app/tools/hash/page.tsx` inherits the MAC page chrome exactly: `<main className="mx-auto w-full max-w-3xl flex-1 px-4 py-12 sm:px-6 lg:px-8">`, `h1`, island at `mt-8`, then Worked example and FAQ sections at `mt-12`.

1. `h1` "Hash Generator" (Display).
2. `HashToolLoader` -> fixed-height skeleton -> `HashTool` island (D-01), containing in order:
   a. **Input block** - label row, textarea, meta row, hint block, conditional notice slot
   b. **Verify block** - "Expected checksum" field + live result line (D-17: between the textarea and the rows)
   c. **Digests block** - `h2` "Digests", output toolbar (encoding toggle, copy-all format toggle, Copy all button), then 10 stacked digest rows in `ALGORITHMS` order (D-10)
3. Worked example section (static, server-rendered).
4. FAQ section (static, server-rendered; JSON-LD from the same `faqItems`).

Layout decision [DEFAULT]: the verify block stays between the textarea and the rows (D-17). To keep the SHA-256 row near the fold at 1280x800, the textarea is 3 rows tall (96px), the byte count sits in the label row above it, "Copy link" sits alone in a compact meta row below it, and the verify label+input share one row at `sm:` and up. At 320px everything stacks single-column.

Gap rhythm inside the island: `flex flex-col gap-8` between the three blocks (32px, matches MacTool); `gap-2` (8px) between a label and its control; `gap-2` between digest rows.

Role assignments for this page:
- **Display:** page `h1` only.
- **Heading:** island `h2` "Digests"; "Worked example"; "FAQ".
- **Body (16px/400):** textarea value (Geist Mono); verify input value (Geist Mono); every digest value (Geist Mono); FAQ answers; worked-example prose.
- **Body, primary digest:** the SHA-256 digest value is 16px **600** Geist Mono (the only digest value in semibold) - this is the "visually emphasized" treatment in D-10 alongside the left accent bar.
- **Label (14px/600):** textarea label, verify label, toolbar group labels ("Encoding", "Copy all as"), digest row algorithm names, toggle items, button captions, badge text, FAQ questions.
- **Small supporting text (14px/400 / 1.4, `text-muted-foreground`):** byte count, hint lines, link notice, notices, verify result line, "Always hex" note. Same size as Label but weight 400, so no new size/weight is introduced.

## Color

60/30/10 split, inherited unchanged (values live in `app/globals.css`, both themes):

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` | `#020617` | Page background |
| Secondary (30%) | `#F1F5F9` | `#0F172A` | Digest row surfaces, skeleton, worked-example and FAQ surfaces |
| Accent (10%) | `#0891B2` cyan-600 | `#22D3EE` cyan-400 | See reserved list |
| Destructive | `#DC2626` red-600 | `#EF4444` red-500 | Hash-engine failure notice only (see below) |

Accent reserved for (explicit list, never "all interactive elements"):
- Copy icon/label color on every copy control: per-row copy buttons, "Copy all digests", "Copy link", and their "Copied!" state
- Left accent bar (`border-l-4 border-l-primary`) on the SHA-256 primary row
- MATCH state: matched row border (`border-primary`) + tint (`bg-primary/10`) + the `CircleCheck` icon inside the MATCH badge and verify result line
- Active (`data-[state=on]`) item of the encoding and copy-all format toggles (`bg-primary/10 text-primary`, UUID precedent)
- Keyboard focus ring (inherited global rule)

Text is never set in accent color for body copy. MATCH badge text, verify result text, digest values and labels stay `text-foreground` / `text-muted-foreground`, so contrast does not depend on cyan-600 against white (about 3.7:1, below AA for 14px text).

Meaning is never carried by color alone (D-13, D-18, QUAL-05):
- MATCH = tinted row **and** `CircleCheck` icon **and** the word "Match".
- Security labels = `ShieldAlert`/`Info` icon **and** words ("Not for security", "Error detection only"), `text-foreground` on `variant="outline"` badges.
- No match = `CircleX` icon **and** the words "No match". Neutral `text-foreground`, never red (D-18).

Destructive is used in exactly one place [DEFAULT]: the hash-engine failure notice ("Couldn't compute digests in this browser...", `TriangleAlert` + `text-destructive`, `role="alert"`). It is a genuine malfunction, unlike a verify mismatch or a long input. Copy failure keeps the Phase 1-5 neutral `text-muted-foreground` treatment. Everything else is neutral.

Dark mode: no per-component color is hard-coded; every surface and text color uses the semantic tokens above (`bg-secondary`, `border-border`, `text-foreground`, `text-muted-foreground`, `text-primary`, `bg-primary/10`, `border-primary`). The skeleton, rows, badges, toggles, and notices must be checked in both themes at 320px.

## Component Specs

### Input block
- Label row: `Label` "Text to hash" (Label role) on the left, the byte count on the right (`flex items-baseline justify-between gap-2`). Byte count renders `{N} bytes (UTF-8)`, `1 byte (UTF-8)` for N = 1, `0 bytes (UTF-8)` for empty; `tabular-nums`; `data-testid="hash-bytes"`. Computed with `encodeText(text).length` (D-08).
- Textarea (`id="hash-input"`, `data-testid="hash-input"`): `rows={3}`, `font-mono text-base md:text-base leading-[1.5] field-sizing-fixed min-h-[96px] max-h-[320px] resize-y overflow-y-auto break-all`. `field-sizing-fixed` is mandatory: the shadcn textarea ships `field-sizing-content`, which would auto-grow without bound on a 1 MiB paste and make island height non-deterministic.
- D-24 attributes exactly: `spellCheck={false}`, `autoCorrect="off"`, `autoCapitalize="off"`, `autoComplete="off"`, `data-1p-ignore`, `data-lpignore="true"`, `data-form-type="other"`. No `onKeyDown` touching Enter.
- Placeholder: "Type or paste text to hash" (visible only when empty).
- Focus while the value still equals the untouched sample selects all after a `requestAnimationFrame` (D-03, avoids mouseup collapsing the selection).
- Meta row below the textarea: "Copy link" `Button` (`variant="outline"`, `h-11`, `Link` icon, accent-tinted) left-aligned under the textarea at every width, content-width (not full-width).
- Hint block (14px/400 muted, always rendered, `id="hash-input-meta"`, referenced by the textarea's `aria-describedby`), two short paragraphs:
  1. D-09 hint (copy below).
  2. Link notice (D-21): "The link contains your text."
- Notice slot (conditional, `min-h` not reserved because notices only appear after the user acts or when a `?text=` load is non-trivial; first paint of the default sample renders no notice). Notices stack in this order, each `flex items-start gap-2 text-[14px] leading-[1.4]` with a 16px leading icon:
  - Empty input: `Info`, muted (D-04)
  - Soft cap exceeded: `Info`, muted (D-07)
  - Link unavailable (over 2,000 encoded chars, or text cannot be encoded): `Info`, muted, linked to the Copy link button with `aria-describedby`
  - Restore affordance after an `Esc` reset of non-sample text: `Undo2` + ghost `Button` "Restore your text" **[DEFAULT, see Flags]**
  - Hash-engine failure: `TriangleAlert`, `text-destructive`, `role="alert"`

### Verify block (D-17..D-19)
- Row at `sm:` and up: `Label` "Expected checksum" (fixed `sm:w-[160px] shrink-0`) + `Input` (`id="hash-verify"`, `data-testid="hash-verify"`, `font-mono`, `maxLength={4096}`, same D-24 autofill-ignore attributes, `spellCheck={false}`). At 320px: label above input, full width.
- Placeholder: "Paste a checksum, e.g. sha256:... or a sha256sum line".
- Result line directly below (`aria-live="polite"`, `data-testid="hash-verify-result"`, `min-h-[24px]` always rendered so the block height is stable, 14px/400). States:
  - `idle` (field empty): renders nothing visible (empty live region).
  - `match`: `CircleCheck` (accent) + "Matches {labels}." where labels are the matching algorithm labels joined with " and " / ", " (e.g. "Matches SHA-256.").
  - `no-match`: `CircleX` (muted) + "No match. This value doesn't equal any digest of the current text." If the value is non-hex or its length is not in {8, 32, 40, 56, 64, 96, 128}, append the hint sentence: "Expected 8, 32, 40, 56, 64, 96 or 128 hex characters; got {N}." (hint, not an error).
  - `pending` (digests stale, D-06): `LoaderCircle` + "Comparing...". Never asserts a match against stale digests.
- Re-evaluates whenever settled digests change (D-19); `Esc` clears the field.
- Matched row treatment: see Digest rows.

### Digests block
- `h2` "Digests" (Heading role).
- Output toolbar: `flex flex-wrap items-end gap-x-4 gap-y-2`. Two groups plus the action:
  1. Encoding group: `Label` "Encoding" (id for `aria-labelledby`) over a `ToggleGroup` (`type="single"`, `variant="outline"`, `value` = `"hex" | "HEX" | "base64"`) with items "hex" (`aria-label="Lowercase hex"`), "HEX" (`aria-label="Uppercase hex"`), "Base64". Default "hex". Ignore the `""` deselect value so one is always selected (D-11). Toggling re-formats stored bytes only, never re-hashes.
  2. Copy-all group: `Label` "Copy all as" over a `ToggleGroup` with items "Labeled list" (default) and "Checksum lines" (D-15), then the "Copy all digests" `Button` (outline, `h-11`, accent text, `Copy`/`Check` swap) next to it. Wraps beneath at 320px.
- Copy-all payloads: labeled list = `{LABEL}: {digest}` per line in the current display encoding; checksum lines = `# {LABEL}` + `{lowercase hex}  -` per algorithm, always lowercase hex regardless of the encoding toggle (D-15/D-16). Snapshot the text at click time.
- Rows: `flex flex-col gap-2` container, `data-testid="hash-rows"`, `aria-busy` while stale.

### Digest row (stacked layout at every width)
`<div data-testid="hash-row-{id}">` with `flex flex-col gap-1 rounded-md border border-border bg-secondary px-4 py-3`, two lines:
1. **Header line** `flex flex-wrap items-center gap-x-2 gap-y-1`: algorithm label (Label role, `text-muted-foreground`), then badges, then the copy button pushed right (`ml-auto`, 44x44, `rounded-full`, accent icon, MacTool `FormatRow` button classes).
2. **Value line**: `data-testid="hash-row-{id}-value"`, `min-w-0 font-mono text-base leading-[1.5] break-all text-foreground`. Wraps at every width; no horizontal scroll (D-14, INT-03). Never `overflow-x-auto`, never `truncate`.

The stacked layout (not MAC's inline `w-[110px]` label) is deliberate: a 128-character SHA-512/SHA3-512 digest needs the full row width at 320px.

Row variants:
- **Primary (SHA-256):** adds `border-l-4 border-l-primary` and the value in 600 weight. Target of the Ctrl/Cmd+C shortcut; shortcut confirmation shows the same `Check`/"Copied!" state on this row's copy button.
- **Security badge rows** (driven by `notForSecurity`, D-13): MD5 and SHA-1 show `Badge variant="outline"` with `ShieldAlert` icon + "Not for security"; CRC32 shows `Badge variant="outline"` with `Info` icon + "Error detection only". All other rows show no badge. Text always visible inline, no tooltip, no modal.
- **Matched (verify):** `border-primary bg-primary/10` replaces the default border/background (primary row keeps its 4px left bar), plus `Badge variant="outline" className="border-primary"` with `CircleCheck` (accent) + "Match", placed after the security badge if both apply. Multiple rows can match simultaneously.
- **CRC32 under Base64:** value stays hex (D-11) and the header adds the muted note "Always hex" (14px/400) so the user is not surprised.
- **Stale** (result text differs from current text, D-06): row content `opacity-60`, layout unchanged, no flicker, `aria-busy` on the container. Copy buttons stay enabled and copy what is displayed (D-12).
- **Pending** (initial text came from `?text=` and the first result has not landed; sample digests must never be shown beside non-sample text): value line renders `'0'` repeated to the exact digest length (`bits / 4` chars, 8 for CRC32) in `text-transparent select-none` inside an `animate-pulse rounded bg-muted` wrapper, `aria-hidden`, with an `sr-only` "Computing". Copy button `disabled`. Height therefore matches the settled row (no CLS).
- **Copy button:** `aria-label` `Copy {LABEL} digest`, switching to "Copied!" on success; `Copy`/`Check` icon swap; sibling `sr-only` `aria-live="polite"` span announces "Copied!"; failure shows the neutral line "Couldn't copy - select the text and copy manually." (reused verbatim from Phases 1-5). One `useCopyToClipboard` per row; copy state resets when the displayed value changes (MacTool `useEffect(reset, [value])` pattern).

### Skeleton (HashToolLoader)
`aria-hidden="true"`, `data-testid="hash-tool-skeleton"`, `animate-pulse rounded-md border border-border bg-secondary`, responsive fixed height: `h-[<N1>px] sm:h-[<N2>px]`. Starting estimates from the layout above are about 1960px below `sm` (320-639px) and about 1600px at `sm` and up. These are estimates, not contract values: the executor must measure the settled island at 320, 375, 768 and 1280 widths in Playwright and pin `N1`/`N2` to the 320px and 1280px measurements (the two worst-case wraps). The single-block skeleton precedent (MAC `h-[420px]`) is not enough here because SHA-512/SHA3-512 wrap to about 5 lines at 320px.

### Registry card and nav (INTG-01)
Rendered by existing components from one registry entry; no design work beyond: icon `Hash` (add to `ICONS` in `components/ToolCard.tsx`; a missing entry silently falls back to the UUID icon), card category label "Encode" (already in `CATEGORY_LABELS`), card description clamped to two lines (keep the registry `description` short enough). Check the desktop nav still fits 5 links at 640px.

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Page load | Island renders `hello world` and its 10 precomputed digests synchronously from constants; no worker call on mount for the sample (D-02, TEXT-01) |
| `?text=` on load | Read once; textarea shows that text; rows show the Pending state until the worker returns; the address bar is never written while typing (D-20) |
| Focus textarea holding the untouched sample | Select all; first keystroke replaces the sample (D-03) |
| Typing / pasting | Calls `HashClient.start()`; previous digests stay visible (stale, dimmed to 60%) until the latest result lands; stale/cancelled results never overwrite newer ones (D-05/D-06). No debounce below the 1 MiB soft cap; ~150ms debounce above it |
| Empty textarea | Valid; shows empty-string digests plus the "Empty input" notice, never blank rows or an error (D-04) |
| Over 1 MiB | Non-blocking inline notice; hashing still runs (D-07) |
| Encoding / copy-all-format toggle | Re-formats stored bytes only; never calls `start()` (D-11) |
| Row copy / Copy all / Copy link | `useCopyToClipboard`; icon swap + "Copied!" + `aria-live`; auto-reverts after the hook's default 2s |
| Copy link | Copies `window.location.origin + "/tools/hash?text=" + encodeURIComponent(text)`; disabled with an inline reason when the encoded text exceeds 2,000 characters or cannot be encoded (lone surrogate); never touches `history`/`router` (D-21) |
| Expected checksum | Normalized and compared on every digest change; matching rows highlighted; `aria-live` result; `Esc` clears (D-17..D-19) |
| `/` | Focus textarea and select all (hook already ignores `/` inside editable fields) |
| `Esc` | Cancels in-flight job, restores the `hello world` sample and its digests, clears the verify field, clears any engine-error notice; does not reset the encoding or copy-all toggles. Ignored while a dialog (nav Sheet) is open |
| `Ctrl/Cmd+C` outside editable fields | Copies the SHA-256 digest as displayed, with the visible "Copied!" on the SHA-256 row. Skipped when the user has any text selected (`window.getSelection()?.toString()` non-empty) so native copy is never clobbered |
| `Enter` | Unbound everywhere; inserts a newline in the textarea (INT-01) |
| Tab order | Skip link/nav (shell) -> textarea -> Copy link -> verify input -> encoding toggle -> copy-all toggle -> Copy all -> row copy buttons in `ALGORITHMS` order |

Reduced motion: the only animations are `animate-pulse` on skeleton/pending and the `LoaderCircle` spin on "Comparing..."; gate both with `motion-safe:` so `prefers-reduced-motion` users see static blocks.

## Flags for the user

These are auto-mode choices that go beyond, or sit at the edge of, what `09-CONTEXT.md` locked. None contradicts a locked decision.

1. **"Restore your text" after Esc [DEFAULT].** D-23 makes `Esc` restore the sample unconditionally, which silently destroys a long paste (React-driven value changes are not in the textarea's native undo stack). This spec adds a one-line "Restore your text" button after an Esc reset of non-sample text, cleared on the next edit. Remove it to accept data loss exactly as D-23 reads. This was Open Question 2 in `09-RESEARCH.md`.
2. **Soft-cap copy cannot mention file mode.** D-07 wants the warning to suggest file mode, but file hashing is Phase 10. The spec uses neutral copy and records the follow-up in the UI Considerations table. **Resolved 2026-10-15:** accepted as 09-CONTEXT.md D-07a, which amends D-07 (autonomous decision under user delegation).
3. **"No tracking" wording.** Other tools' meta descriptions say "No login, no tracking." D-27 says new wording implying a privacy claim beyond "runs in your browser" needs human approval, so this spec's meta description omits "no tracking". If the owner wants consistency with the other tools, approve that phrase explicitly.
4. **Copy link is absolute** (`window.location.origin + /tools/hash?text=...`), not the relative path written in D-21, so the pasted link works anywhere and on preview deployments (`09-RESEARCH.md` Open Question 4). The 2,000-character cap applies to the encoded `text` value.
5. **Destructive color is used once** (engine-failure notice). Everything else stays neutral, following the MAC precedent.
6. **No visible keyboard-shortcut legend.** No existing tool shows one, so none is added. Shortcuts are discoverable only by convention (`/`, `Esc`, Ctrl/Cmd+C). A legend can be added later across all tools at once.
7. **Skeleton heights** are estimates and must be measured and pinned by the executor (see Skeleton).
