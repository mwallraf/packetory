# Phase 13 — UI Design Contract

> Visual and interaction contract for the Password-mode page at `/tools/password`. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `13-CONTEXT.md` (D-01..D-17, locked, auto-accepted), `ROADMAP.md` Phase 13 SC-1..SC-5, `REQUIREMENTS.md` (PWD-01/02/03/05/06/07/08, POUT-01..05), `10-UI-SPEC.md` (tokens, type scale, focus, About conventions), v1.2 `09-UI-SPEC.md` (accent-text contrast rule), and a code scan of `app/globals.css`, `app/tools/uuid/*`, `app/tools/hash/{HashTool,DigestRow}.tsx`, `components/ui/{input,switch}.tsx`, `lib/hooks/{useCopyToClipboard,useKeyboardShortcut}.ts`, `lib/config/token-classes.ts` and `lib/password/constants.ts`.

This phase adds NO new CSS variables, NO new fonts and NO new dependencies. It uses two Tailwind palette pairs that are new to this page but already in the site's syntax-color family (`sky-700/sky-300` for digits, `amber-700/amber-300` for symbols, as `TOKEN_CLASSES` uses `amber-700/amber-300`). Out of scope here, owned by Phase 14: the Password/Passphrase toggle and passphrase controls, the strength meter, the pool-size and bits line, crack time, registry/nav/landing card/sitemap, final metadata/OG, `ToolAbout`/FAQ/JSON-LD and the final skeleton pin.

## Color

No new CSS variables. All surfaces and text use tokens from `app/globals.css`. Contrast was computed with the WCAG 2.x formula on 2026-11-11 (script in the session scratchpad).

| Role | Value (light / dark) | Usage in this phase |
|------|----------------------|---------------------|
| Dominant (60%) | `--background` `#ffffff` / `#020617` | Page, the Options section, the batch toolbar and the error panel |
| Secondary (30%) | `--secondary` `#f1f5f9` / `#0f172a` | Hero output surface, batch list surface, skeleton, `<kbd>` keys |
| Accent (10%) | `--primary` `#0891b2` / `#22d3ee` | See the reserved list below |
| Destructive | `--destructive` `#dc2626` / `#ef4444` | The fail-closed generation error only |
| Muted text | `--muted-foreground` `#64748b` / `#94a3b8` | Hints, the scale numbers, the shortcut line, the batch count, set examples. Only on `bg-background` (4.76:1 light, 7.87:1 dark). |
| Border | `--border` `#e2e8f0` / `#1e293b` | Hero and list borders, row dividers, the `<kbd>` border |

Accent reserved for (explicit list):
1. Copy controls: the icon and caption of the hero Copy button, every batch-row copy button and Copy all, in both the resting and "Copied!" states (`text-primary`, Hash/UUID precedent).
2. The checked track of the five `Switch`es (existing `data-checked:bg-primary`).
3. The native range input's thumb and fill (`accent-primary`).
4. The keyboard focus ring (`ring-ring/50`) on every control.

The accent is NOT used for Regenerate (it is a neutral outline button, see Decisions), for any body or hint text, for the password characters, or for borders.

Contrast rules (binding):
- Muted text never sits on `bg-secondary`. In light mode `#64748b` on `#f1f5f9` is 4.34:1, which fails AA. Any 14px text inside the hero or the batch list uses `text-foreground`. Hints live outside those surfaces on `bg-background`.
- Destructive text never sits on `bg-secondary`. In light mode `#dc2626` on `#f1f5f9` is 4.41:1, which fails. The error panel therefore uses `bg-background`.
- Accent text is limited to the copy captions above (an accepted site-wide precedent: cyan-600 on white is 3.68:1). No sentence or value is ever set in the accent.

### Output coloring (PWD-08, D-09)

| Character class | Classes | Light on `#f1f5f9` | Dark on `#0f172a` |
|-----------------|---------|--------------------|-------------------|
| Letters `A–Z a–z` | `text-foreground` | 16.30:1 | 17.06:1 |
| Digits `0–9` | `text-sky-700 dark:text-sky-300` | 5.42:1 | 10.71:1 |
| Symbols (everything else) | `text-amber-700 dark:text-amber-300` | 4.58:1 | 12.38:1 |

All pass WCAG AA 4.5:1 at 16px regular, which is the smallest size used (batch rows). Classification is by character code: `A–Z`/`a–z` are letters, `0–9` are digits, and every other printable ASCII character is a symbol. Consecutive characters of the same class are one `<span>`, the spans are adjacent with no whitespace or text nodes between them, and the parent has no `gap`/`space-x`. Each span may carry `data-kind="letter|digit|symbol"` for tests. That is the only `data-*` attribute allowed on the output, and it never holds characters.

Color is supplementary, not the only carrier of meaning: every character stays legible by shape, so WCAG 1.4.1 is not engaged. Do not add a legend in this phase.

## Interaction & Layout Contract

### Visual hierarchy / focal point

- Primary anchor: the password itself. It is a 20px/600 Geist Mono value in the `bg-secondary` hero directly under the h1, in the first viewport at 320px and at desktop width.
- Second: the hero Copy button (accent caption "Copy"), immediately below the value, first in tab order after the page chrome.
- Third: Regenerate (neutral outline), next to Copy.
- Then the Options section under a 32px gap, on the plain page background, with an h2 "Options", 14px labels and muted hints. Options never sit above the output (D-05, tool-first).

### Page shell (D-01, D-04)

```
<div class="flex flex-1 flex-col bg-background">
  <main class="mx-auto w-full max-w-3xl flex-1 px-4 py-12 sm:px-6 lg:px-8">
    <h1 class="text-[32px] leading-[1.2] font-semibold text-foreground">Password Generator</h1>
    <div class="mt-8"><PasswordToolLoader /></div>
  </main>
</div>
```

There is no intro paragraph, no `ToolAbout` and no FAQ in this phase. The page never imports `PasswordTool` directly.

### Island structure

```
<div class="flex flex-col gap-8">
  <div data-testid="password-output-zone">   ← exactly one of: hero | batch | error
  <section aria-labelledby="password-options-heading"> … </section>
  <span aria-live="polite" class="sr-only" data-testid="password-status">{fixed phrase}</span>
</div>
```

The live region is always mounted, including in the error state, and sits outside the output zone so it survives hero/batch switches.

### Hero (batch = 1, D-10)

```
<div data-testid="password-hero" class="flex flex-col gap-4 rounded-md border border-border bg-secondary p-4">
  <div data-testid="password-output" translate="no" spellcheck="false"
       class="font-mono text-[20px] leading-[1.4] font-semibold break-all select-all text-foreground">
    {runs as spans}
  </div>
  <div class="flex flex-wrap items-center gap-2">
    [Copy]  [Regenerate]
  </div>
  {copyError && <p class="text-[14px] leading-[1.4] font-normal text-foreground">Couldn't copy — select the text and copy manually.</p>}
</div>
```

- The value is above the actions at every width, and Copy and Regenerate sit side by side (they fit at 320px: about 100px + 140px inside 256px). This also keeps the buttons at a stable horizontal position whatever the password length.
- The output `div` has no `tabIndex`, `role`, `title`, `aria-*` or `contenteditable`. It is not an `<input>`, `<textarea>`, `<output>` or any form-associated element, and no ancestor is a `<form>` (D-08, D-09).
- Copy button: `<button type="button" data-testid="password-copy" aria-label={copied ? "Copied!" : "Copy password"} class="inline-flex h-11 min-w-11 shrink-0 items-center justify-center gap-2 rounded-full px-4 text-primary outline-none transition-colors hover:bg-muted focus-visible:ring-[3px] focus-visible:ring-ring/50">`. At rest it shows `Copy` (size-5) plus the caption "Copy". When confirmed it shows `Check` (size-4) plus "Copied!" for about 2s.
- Regenerate button: `<button type="button" data-testid="password-regenerate" class="inline-flex h-11 shrink-0 items-center justify-center gap-2 rounded-full border border-border px-4 text-foreground outline-none transition-colors hover:bg-muted focus-visible:ring-[3px] focus-visible:ring-ring/50">` with `RefreshCw` (size-5, `aria-hidden`) and the caption "Regenerate". Its accessible name is its visible text.
- There is no animation on a new password (no fade, no slide). The value swaps instantly.

### Batch (batch = 2..20, D-10)

```
<div data-testid="password-batch" class="flex flex-col gap-2">
  <div class="flex flex-wrap items-center gap-2">
    <p class="mr-auto text-[14px] leading-[1.4] font-semibold text-muted-foreground">{n} passwords</p>
    [Copy all]  [Regenerate]
  </div>
  {copyAllError && <p class="text-[14px] leading-[1.4] font-normal text-muted-foreground">Couldn't copy — select the text and copy manually.</p>}
  <ul data-testid="password-batch-list" class="flex flex-col divide-y divide-border rounded-md border border-border bg-secondary px-4">
    <li key="{generation}-{index}" data-testid="password-row" class="flex items-start gap-2 py-1">
      <div data-testid="password-row-value" translate="no" spellcheck="false"
           class="min-w-0 flex-1 py-2 font-mono text-[16px] leading-[1.5] font-normal break-all select-all text-foreground">{runs}</div>
      [row Copy]
    </li>
    …
  </ul>
</div>
```

- The toolbar is on `bg-background`, so the muted count passes contrast. "{n} passwords" is always plural because n ≥ 2 in this view.
- Copy all is accent and has the same classes as the hero Copy: `Copy` + "Copy all", confirming as `Check` + "Copied!". Its accessible name is "Copy all passwords" at rest and "Copied!" while confirmed. It copies `results.join("\n")` with no trailing newline.
- Row copy is icon-only (`Copy` size-5) and becomes `Check` (size-4) + "Copied!" while confirmed. It has `data-testid="password-row-copy"`, and `aria-label` is `Copy password {index+1}` at rest and "Copied!" while confirmed. Each row has its own `useCopyToClipboard`, so confirmations never bleed between rows.
- There is no row index number in the UI. The accessible name carries the position, and a muted index would fail contrast on `bg-secondary`.
- There is no inner scroll container. The list grows in-page (at most 20 rows). Row keys are `${generation}-${index}`, never the value.
- Row copy error: a `w-full` line under that row's value, `text-[14px] leading-[1.4] text-foreground`, with the same copy-failure text.

### Fail-closed error (D-03, PWD-07)

It replaces the hero or batch entirely. No password, no Copy, no Copy all and no Regenerate are rendered:

```
<div data-testid="password-error" class="flex items-start gap-2 rounded-md border border-destructive/30 bg-background p-4">
  <TriangleAlert aria-hidden="true" class="mt-1 size-4 shrink-0 text-destructive" />
  <div role="alert" class="flex flex-col gap-2">
    <p class="text-[16px] leading-[1.5] font-normal text-destructive">{error sentence}</p>
    <p class="text-[14px] leading-[1.4] font-normal text-muted-foreground">{next step}</p>
  </div>
</div>
```

- The options stay editable. Every later commit, Enter or Esc tries again and fails closed in the same way. No retry button is shown, because a missing Web Crypto does not come back within a page session.
- The live region announces nothing for an error. `role="alert"` carries it.

### Options section (D-05, D-06)

```
<section aria-labelledby="password-options-heading">
  <h2 id="password-options-heading" class="text-[20px] leading-[1.2] font-semibold text-foreground">Options</h2>
  <div class="mt-4 grid grid-cols-1 gap-6 sm:grid-cols-2">
    [Length — sm:col-span-2]
    [Character sets]   [Symbol set]
    [Avoid look-alikes] [Batch count]
  </div>
  <p data-testid="password-shortcuts" class="mt-6 text-[14px] leading-[1.4] font-normal text-muted-foreground">…</p>
</section>
```

The DOM and tab order follow reading order: length number → slider → Uppercase → Lowercase → Digits → Symbols → symbol-set input → Avoid look-alikes → batch count.

#### Length (PWD-02)

```
<div class="flex flex-col gap-2 sm:col-span-2">
  <div class="flex flex-wrap items-center gap-2">
    <Label htmlFor="password-length" id="password-length-label">Length</Label>
    <Input id="password-length" data-testid="password-length" type="text" inputMode="numeric" class="h-11 w-20 text-base md:text-base" … />
    <span class="text-[14px] leading-[1.4] text-muted-foreground">characters</span>
  </div>
  <input type="range" data-testid="password-length-slider" aria-labelledby="password-length-label"
         min={LENGTH_MIN} max={LENGTH_MAX} step={1} value={options.length}
         class="h-11 w-full cursor-pointer rounded-full accent-primary outline-none focus-visible:ring-[3px] focus-visible:ring-ring/50" />
  <div aria-hidden="true" class="flex justify-between text-[14px] leading-[1.4] tabular-nums text-muted-foreground"><span>{LENGTH_MIN}</span><span>{LENGTH_MAX}</span></div>
  {lengthError && <span id="password-length-hint" data-testid="password-length-hint" class="text-[14px] leading-[1.4] text-muted-foreground">Enter a number between {LENGTH_MIN} and {LENGTH_MAX}</span>}
</div>
```

- The number input keeps a draft string. A valid integer in range commits and regenerates. Empty, out-of-range or non-integer input sets `aria-invalid` and `aria-describedby="password-length-hint"`, shows the hint and keeps the last committed value. On blur the draft is clamped (empty goes back to the committed value) and resynced.
- The slider commits on every `input` event. While the slider is moved, the number draft mirrors it and any length error clears.
- Both controls have the accessible name "Length". The slider's value is announced natively (`aria-valuenow`), and no `aria-valuetext` is added.

#### Character sets (PWD-03)

```
<div role="group" aria-labelledby="password-sets-label" class="flex flex-col gap-2">
  <span id="password-sets-label" class="text-[14px] leading-[1.4] font-semibold text-foreground">Character sets</span>
  ×4: <div class="flex min-h-11 items-center gap-4">
        <Switch id="password-set-uppercase" data-testid="password-set-uppercase" … />
        <Label htmlFor="password-set-uppercase">Uppercase <span class="font-mono font-normal text-muted-foreground">A–Z</span></Label>
      </div>
  {lockHint}
</div>
```

- The rows are, in order: Uppercase `A–Z`, Lowercase `a–z`, Digits `0–9`, Symbols (no example, because the set is user-defined).
- When exactly one set is on, that switch is `disabled` (it keeps `checked`, and the existing `data-disabled:opacity-50` applies to the switch only, while its label stays full contrast). The hint `<p id="password-sets-lock-hint" data-testid="password-sets-lock-hint" class="text-[14px] leading-[1.4] text-muted-foreground">At least one character set must stay on</p>` renders, and the disabled switch references it with `aria-describedby`. When two or more sets are on, the hint is not rendered.
- `role="group"` is used instead of `<fieldset>`, so the panel contains no form-associated element.

#### Symbol set (PWD-05)

```
<div class="flex flex-col gap-2">
  <Label htmlFor="password-symbols">Symbol set</Label>
  <Input id="password-symbols" data-testid="password-symbols" type="text" class="h-11 font-mono text-base md:text-base" disabled={!options.symbols} aria-describedby="password-symbols-hint" … />
  <p id="password-symbols-hint" data-testid="password-symbols-hint" class="text-[14px] leading-[1.4] text-muted-foreground">{hint}</p>
</div>
```

- The draft is free text. Generation uses `normalizeSymbols(draft)` live. On blur the draft is rewritten to the normalized value. It is never normalized per keystroke.
- The hint has exactly one state, in this priority order:
  1. Symbols off: "Turn on Symbols to use this set". The input is disabled and keeps its value.
  2. Draft normalizes to the default because it is empty or has no usable characters: "Empty, so the default set is used".
  3. Otherwise: "Up to {SYMBOL_SET_MAX} printable ASCII symbols. Letters, digits, spaces and repeats are removed when you leave the field."
- There is no `maxLength` on the input, so pasting a mixed string still works and is capped by normalization on blur. Long drafts scroll inside the input natively.

#### Avoid look-alikes (PWD-06)

```
<div class="flex flex-col gap-2">
  <div class="flex min-h-11 items-center gap-4">
    <Switch id="password-lookalikes" data-testid="password-lookalikes" aria-describedby="password-lookalikes-hint" … />
    <Label htmlFor="password-lookalikes">Avoid look-alikes</Label>
  </div>
  <p id="password-lookalikes-hint" class="text-[14px] leading-[1.4] text-muted-foreground">Removes <span class="font-mono">{LOOK_ALIKES split, joined with spaces}</span></p>
</div>
```

The hint is always visible. The characters come from `LOOK_ALIKES` and are never restated as literals.

#### Batch count (POUT-02)

Same layout as Length's label row: `Label` "Batch count" and an `Input` `id="password-batch-count"` `data-testid="password-batch-count"` `type="text" inputMode="numeric" class="h-11 w-20 text-base md:text-base"`. It uses the same draft/commit/blur-clamp rules as Length. The error hint is `Enter a number between {BATCH_MIN} and {BATCH_MAX}` (`data-testid="password-batch-count-hint"`, `aria-describedby` while invalid).

#### Input attributes (D-08), on all three text inputs

`autoComplete="off"`, `spellCheck={false}`, `autoCorrect="off"`, `autoCapitalize="off"`, `data-1p-ignore`, `data-lpignore="true"`, `data-bwignore`, `data-form-type="other"`. The range input gets `autoComplete="off"`. Nothing is wrapped in a `<form>`, and no input has `name` or `type="password"`.

#### Shortcut hint (D-14)

Rendered as one line that wraps naturally:

`Keyboard: <kbd>/</kbd> length · <kbd>Enter</kbd> regenerate · <kbd>Esc</kbd> reset options · <kbd>Ctrl/Cmd</kbd>+<kbd>C</kbd> copy (single password)`

Each `<kbd>` uses `rounded-sm border border-border bg-secondary px-1 font-mono text-[14px] leading-[1.4] text-foreground`. Text inside `<kbd>` is foreground on secondary (16.30:1), not muted.

### Keyboard (POUT-04, D-14)

| Key | Effect | Guard |
|-----|--------|-------|
| `/` | Focuses the Length number input and selects its text | Hook: not inside an editable target (the range input counts as editable) |
| Enter | Regenerates with the committed options (an invalid draft keeps the last valid value) | Hook: skipped on buttons, switches (`button[role=switch]`), radios, links and `summary`. It fires from the length, batch and symbol inputs and from the slider. |
| Esc | Resets every option to `DEFAULT_OPTIONS`, resets all three drafts and the hints, regenerates, and writes the bare `/tools/password` URL. Focus stays where it was. | Hook: IME-composition guard |
| Ctrl/Cmd+C | Copies the hero value through the hero's copy hook, so the hero shows "Copied!" | `undefined` when batch > 1. A local guard returns early when `window.getSelection()?.toString()` is non-empty. The hook already skips editable targets. |

There is no keyboard trap. Tab order is DOM order, and no `tabIndex` greater than 0 is used anywhere.

### Live region (D-11, POUT-05)

There is one `aria-live="polite"` `sr-only` span per tool (`data-testid="password-status"`). It only ever contains one of these fixed strings, or is empty:

| Trigger | Announcement |
|---------|--------------|
| Hero, row or keyboard copy succeeded | `Copied` |
| Copy all succeeded | `Copied all passwords` |
| Regenerate click, Enter or batch-count commit, at batch = 1 | `New password generated` |
| Same triggers at batch = n > 1 | `{n} new passwords generated` |
| Esc reset | `Options reset. New password generated` |

- Option changes from the slider, length input, switches, symbol set or look-alikes do NOT announce. The control's own state change is announced natively, and announcing on every slider step would flood screen readers.
- Repeated identical announcements must re-announce. Clear the region to `""` first and then set the phrase on the next tick (for example with `setTimeout(…, 0)`, cleaned up on unmount). Never append the value, a counter or invisible characters.
- The region never contains, and is never derived from, password characters.

### URL (D-13)

`history.replaceState(null, "", qs ? `${pathname}?${qs}` : pathname)` runs once on mount and on every commit. It has no visual surface and shows no notice when a hostile URL is rewritten (the page silently loads the clamped options).

### Skeleton (D-17, provisional)

```
<div data-testid="password-skeleton" aria-hidden="true" class="flex flex-col gap-8 h-[{H320}px] sm:h-[{Hsm}px]">
  <div class="h-[{hero}px] animate-pulse rounded-md border border-border bg-secondary motion-reduce:animate-none" />
</div>
```

- `H320` and `Hsm` are measured from the real island in its default single-result state, at 320px and at ≥640px. They are recorded in the SUMMARY, and `{hero}` is the measured hero height. These are provisional pins only. Phase 14 makes the final pin and the CLS gate.
- The skeleton contains no text, no digits or symbols and no `password-output` testid.

### Responsive & theme

- 320px: no horizontal page overflow at length 128 in either the hero or the batch. Values wrap with `break-all`. The grid is one column. The action row and toolbar wrap rather than overflow.
- ≥640px (`sm`): two-column options grid, with Length spanning both columns.
- Dark mode: tokens plus the `dark:` variants of the digit and symbol classes. No other per-component dark overrides.
- Motion: only the existing switch thumb transition, button `transition-colors` and the skeleton pulse, which is disabled under `prefers-reduced-motion`.

## Decisions made without user input (review at UAT)

The run mode asked for no questions. Each call below follows CONTEXT.md first, then the existing site patterns, then shadcn/Tailwind conventions.

| # | Decision | Basis |
|---|----------|-------|
| 1 | Regenerate is a neutral outline pill (`border-border text-foreground`), not accent as on UUID. The accent stays on copy controls only, so Copy reads as the primary action. | Hash 09-UI-SPEC accent reserved list. Gives a clear CTA hierarchy. |
| 2 | Hero layout: value on top, then Copy and Regenerate side by side below it, at every width (including 320px). | D-10 discretion item. Keeps the button positions stable as the length changes. |
| 3 | The hero Copy shows a visible caption "Copy" (UUID's hero is icon-only). Batch-row copy stays icon-only. | Clearer primary CTA. Rows stay compact at 320px. |
| 4 | Copy `aria-label` swaps to "Copied!" while confirmed, and the live region says "Copied". | UUID/Hash precedent. Resting names match D-10 exactly. |
| 5 | No row index numbers in the batch list. | Muted text on `bg-secondary` fails AA (4.34:1), and the accessible names already carry the position. |
| 6 | No inner `ScrollArea` for the batch. The list grows in-page (max 20). | Avoids a nested scroll on mobile. 20 rows is bounded. |
| 7 | An `h2` "Options" over the options grid, with a 2-column grid at `sm`: Length full width, then [Character sets, Symbol set] and [Avoid look-alikes, Batch count]. | Heading outline for screen readers. Keeps the Symbols switch next to the symbol set. |
| 8 | The live region announces only on Regenerate, Enter, Esc, batch commit and copies. It never announces on slider or switch changes. Added the fixed phrase "Options reset. New password generated" for Esc. | Prevents flooding screen readers on slider drags. The phrase is fixed, value-free and still follows D-11. |
| 9 | A distinct, accurate message for `GenerationExhaustedError` instead of reusing the crypto sentence. | The crypto wording would be false for exhaustion. The path is defensive and practically unreachable. |
| 10 | A muted next-step line under the locked crypto sentence, and no retry button. | Error copy needs a solution path. Crypto does not appear mid-session. |
| 11 | Hero value at 20px/600 Geist Mono with line height 1.4. | UUID hero size. 1.4 for multi-line wrapping at 128 characters. |
| 12 | Binding rule: muted and destructive text never on `bg-secondary`. Copy-error text inside the hero and rows uses `text-foreground`, and the error panel uses `bg-background`. | Computed contrast (see Color). |
| 13 | All inputs `h-11` and `text-base md:text-base`. Number inputs are `type="text" inputMode="numeric"`. | 44px touch target, the Hash 16px-input precedent, and UUID's count input (no spinner or wheel surprises). |
| 14 | Autofill opt-outs are a superset of D-08: also `autoCorrect="off"`, `autoCapitalize="off"` and `data-form-type="other"`. | The Hash D-24 attribute set. Harmless and stronger against password managers. |
| 15 | Slider min/max scale numbers under the range input, `aria-hidden`. | Shows the bounds without extra speech. |
| 16 | The set labels show muted mono examples (`A–Z`, `a–z`, `0–9`). | Faster scanning. Part of the label's accessible name. |
| 17 | Symbol hint wording (three states) and the "Turn on Symbols to use this set" state. | D-05 discretion on helper-text wording. |
| 18 | `<kbd>` styling for the shortcut line. This is new on the site, but uses existing tokens only. | D-14 "muted shortcut hint line". |
| 19 | `role="group"` with `aria-labelledby` for the character sets, instead of `<fieldset>`. | Keeps form-associated elements out of the tool (D-08 spirit). |
| 20 | `data-kind` (values `letter`, `digit`, `symbol`) allowed on output spans for tests. It never carries characters. | A testability hook compatible with D-10's no-value-in-`data-*` rule. |
| 21 | Placeholder metadata description avoids any privacy claim. | The privacy wording needs human approval in Phase 14. |
| 22 | The a11y-snapshot assertion in D-16 is read as names, descriptions and live regions, and the output is NOT `aria-hidden` (listed as unresolved above). | The password must remain readable to screen-reader users. |

**New dependencies:** none. The native range input replaces any slider package, and every other piece already exists (`Switch`, `Input`, `Label`, lucide icons, the two hooks).
