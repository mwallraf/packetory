<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR source -> CI runner | Untrusted PR code executes in CI; third-party actions run with repo context. |
| CI/Vercel -> production deploy | The merge gate + deploy pipeline decides what reaches production. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-SC | Tampering | GitHub Actions third-party actions | medium | mitigate | Pin actions to trusted publishers + a fixed major version; use `npm ci` against the committed lockfile; no gating step uses continue-on-error, so a tampered build cannot green the gate. |
| T-05-01 | Elevation of Privilege | deploy credentials | medium | mitigate | Production/preview deploys use Vercel's GitHub integration (no long-lived deploy token committed); any secrets live in Vercel/GitHub settings, never in the repo. |
| T-05-02 | Spoofing | merge gate bypass | high | mitigate | Branch protection requires the named CI checks on main (Task 3 human setup); a PR cannot merge without them, so broken/unreviewed code cannot reach the auto-deploy branch. |
</threat_model>
