</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| page URL / query params -> analytics provider | Query params may contain sensitive values (future MACs, private IPs, hostnames, secrets); the redaction boundary decides what leaves the browser. |
| AI-drafted legal text -> published /privacy page | Privacy/legal wording asserted to users must be accurate and human-approved. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Information Disclosure | analytics query-param reporting | high | mitigate | All reported params pass through the safe-by-default allow-list (redactParams); only explicitly-listed params leave the browser, so a future sensitive param is excluded by default with no code change (D-13). |
| T-04-02 | Repudiation / Compliance | AI-drafted privacy notice | medium | mitigate | The notice is published as a flagged draft and gated behind a blocking human sign-off (Task 3, D-15); it makes no unverified compliance claims. |
| T-04-03 | Information Disclosure | cookie-free analytics | low | accept | Vercel Analytics is cookie-free by design (D-12) and no fingerprinting identifier is introduced (prohibition), so no tracking-cookie surface exists. |
</threat_model>
