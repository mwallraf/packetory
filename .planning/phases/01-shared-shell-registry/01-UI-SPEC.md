## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Icon-only interactive controls (theme toggle, copy buttons, mobile hamburger trigger) must have a minimum 44×44px hit area per QUAL-05/WCAG target-size guidance, achieved via padding around a smaller visual icon (16–20px) rather than by breaking the 4px grid — the icon itself stays on-scale, only the invisible tap target is exempted.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 (semibold) | 1.4 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 32px | 600 (semibold) | 1.2 |

- **Label** — nav links, "Coming soon" badge, IP-widget caption, footer links.
- **Body** — descriptions, privacy-notice prose, tool-card description text.
- **Heading** — tool-card titles, section headings.
- **Display** — landing-page `h1` only (one per page).

**Monospace override:** Geist Mono replaces Geist Sans, at the same size/weight as the role it appears in, specifically for copyable technical strings — in Phase 1 this is the visitor IP address value (Body 16px/400 in Geist Mono). This pattern extends to UUIDs, CIDR blocks, and MAC addresses in later phases.

## Color

60/30/10 split, declared for both themes (SHELL-05 requires light + dark).

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` white | `#020617` slate-950 | Page background |
| Secondary (30%) | `#F1F5F9` slate-100 | `#0F172A` slate-900 | Cards, top nav bar, mobile nav drawer, footer |
| Accent (10%) | `#0891B2` cyan-600 | `#22D3EE` cyan-400 | See reserved list below — confirmed with user 2026-07-21 |
| Destructive | `#DC2626` red-600 | `#EF4444` red-500 | Reserved for destructive actions only — none exist in Phase 1; reserved now for cross-phase consistency starting Phase 2+ |

Accent reserved for (explicit list — never "all interactive elements"):
- Copy-button icon default/hover/active state (IP widget copy button)
- Copy-confirmation checkmark/"Copied!" flash
- Active/current nav-link indicator (underline or icon tint)
- Keyboard focus ring (all interactive elements)
- "Featured" tool-card accent border or badge tint (per registry `featured` flag, D-02)
- Theme-toggle icon

Everything else — card borders, muted "Coming soon" badge, body text, footer links — uses neutral slate tones, not the accent. This keeps the 10% accent legible as "this is clickable/live," not decorative.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Copy IP address" — icon button with `aria-label`; on activation the icon/label swaps to a "Copied!" confirmation for ~2s, then reverts |
| Empty state heading | Not applicable — the tool registry is statically populated at build time and can never render zero cards in production |
| Empty state body | "Coming soon" — badge copy on `status: "planned"` tool cards (Subnet/DNS/MAC placeholders shown in Phase 1 per D-01), rendered muted and non-clickable |
| Error state | Not applicable in Phase 1 — no retryable async operation ships this phase. The visitor-IP widget fails silently by not rendering at all (D-07) rather than showing an error message. The first true error-state UI is Phase 3's inline CIDR validation |
| Destructive confirmation | None in Phase 1 — theme toggle and copy actions are non-destructive and instantly reversible; no destructive-action pattern is needed yet |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 10 covered, 3 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | tool-registry-grid (list-collection) | ✅ covered | Registry is statically imported at build time; TS `ToolDefinition` type requires all fields — a true zero-item grid cannot occur in production, so no empty-state UI is needed. |
| loading | tool-registry-grid (list-collection) | ✅ covered | Grid renders from static data with no client-side fetch — no loading state exists. |
| error | tool-registry-grid (list-collection) | ✅ covered | Same reasoning as loading — no async data source, so no error state is possible. |
| populated | tool-registry-grid (list-collection) | ✅ covered | Flat responsive grid, sorted by `featured` then alphabetically (D-02); `planned`-status tools render the muted, non-clickable "Coming soon" badge variant (D-01, see Copywriting Contract). |
| partial | tool-registry-grid (list-collection) | ✅ covered | `ToolDefinition` requires all fields at compile time — a partially-filled registry entry is a TypeScript error, not a reachable runtime state. |
| overflow / long-text | tool-registry-grid (card description) | 🧪 backstop | Card description clamps to 2 lines (`line-clamp-2`) with no layout shift; full text lives on the tool's own page. Needs a visual test with an intentionally long description string. |
| zero-one-many | tool-registry-grid (list-collection) | ✅ covered | Grid collapses to a single column at 320px (SHELL-06) and does not depend on a specific item count — same layout logic at 1 or many cards. |
| empty | visitor-ip-widget (interactive-control) | ✅ covered | D-07: widget is not rendered at all when the IP can't be determined — no placeholder or error copy is ever shown (see Copywriting Contract "Error state" row). |
| loading | visitor-ip-widget (interactive-control) | ✅ covered | IP is resolved server-side before the page reaches the client (D-05) — no client-visible loading state. |
| long-text | visitor-ip-widget (interactive-control) | 🧪 backstop | IPv6 values (up to 39 chars) must stay fully visible and copyable, never truncated — pill wraps to two lines or reduces type size rather than clipping. Needs a visual test at 320px with a long IPv6 value. |
| overflow | mobile-nav-drawer (nav) | 🧪 backstop | Drawer content scrolls vertically once tool-link count exceeds viewport height as more tools ship; logo + theme toggle stay pinned outside the scroll area (D-04). Needs a visual test once tool count grows past Phase 1's 5 entries. |
| long-text | mobile-nav-drawer (nav) | ✅ covered | Nav uses each tool's `shortName` registry field (kept short by convention) — single-line nav items, no wrap/truncation logic needed. |
| loading / error | theme-toggle (interactive-control) | ✅ covered | Toggle reads/writes `localStorage` synchronously (D-10) — no async operation, so no loading or error state can occur. |
