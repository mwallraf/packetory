<interfaces>
DOM contract on every tool page after 10-04 (from components/ToolAbout.tsx):
- main > ... > `section[data-testid="about-tool"]` is main's last element child. It contains `script[type="application/ld+json"]`, `h2#about-heading` ("About this tool"), and a `div.mt-4` holding `details[data-testid="{slug}-worked-example"]` and then `details[data-testid="{slug}-faq"]`, each with a summary.
- FAQ items: `[data-testid="{slug}-faq-item"]` with exactly two p children (question, answer).
- Config only: `[data-testid="config-worked-example-preview"]` is a horizontally scrolling code pane inside the worked example (it scrolls by design and must be excluded from per-element overflow checks).

This plan does not use `openAbout` (tests/e2e/helpers/about.ts): its tests click or focus the summaries directly. 10-06 imports it for the 320px layout test.

Registry: `tools` from tools/registry.ts. Slugs uuid, subnet, dns, mac, hash, config; all status "active". Use `tools.filter((t) => t.status !== "planned")`. From tests/e2e, import it with the relative path "../../tools/registry".

faq-data modules (all import-free, safe in the vitest node environment): app/tools/{uuid,subnet,dns,mac,hash,config}/faq-data.ts, each exporting `faqItems`.

Source-guard analog: app/hash-smoke/page.test.tsx reads source files with readFileSync and path.join. app/layout.tsx legitimately uses the raw-HTML prop for the theme init script, so the guard must key on the JSON-LD script type and the FAQPage literal, not on the raw-HTML prop name, when it scans the whole tree.

Raw-HTML note: the Next.js RSC flight payload inlined in the HTML also contains the JSON-LD props as an escaped string. Count the literal tag opening `<script type="application/ld+json"` rather than the bare type string, and look for an `open` attribute only inside `<details ...>` tags.

JS-off note: with `javaScriptEnabled: false` page scripts do not run, so the parity helper uses only locators, the `request` fixture and plain string checks on the fetched HTML, with no in-page script evaluation. The tool islands are `ssr:false` loaders, so with JS off the server HTML carries the page shell and the About area only.
