# Phase 10 — UI Design Contract

> Visual and interaction contract for the shared "About this tool" area and Config parity. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `10-CONTEXT.md` (D-01..D-14, locked), `REQUIREMENTS.md` (INFO-01..05, CFG-01..03), existing code scan (`app/globals.css`, `components/ui/button.tsx`, `components/ToolCard.tsx`, `app/tools/*/page.tsx`, `app/tools/config/ConfigTool.tsx`).

## Interaction & Layout Contract

### Visual hierarchy / focal point

- Primary visual anchor on every tool page: the tool's own output (UUID list, subnet result, DNS records, MAC result, hash digest, Config preview pane). It sits directly under the h1 in the first viewport at full-contrast foreground color, 16px+ values and the existing result surfaces.
- The About area is strictly secondary: muted 14px h2, muted 16px/600 summary labels, no background, no accent color, closed on load. It must never compete with the tool output for attention (no tinted panel, no accent, no icon beyond the 16px chevron). Contrast is deliberately lower at rest and rises to full foreground only on hover or when opened.
- The 64px `mt-16` gap plus the `border-t` rule is the single visual break between the primary (tool) and secondary (About) zones.

### About area structure (all six pages)

```
<main class="mx-auto w-full max-w-3xl (Config: max-w-6xl) flex-1 px-4 py-12 sm:px-6 lg:px-8">
  <h1/> [Config: intro <p/>]
  <div class="mt-8"> <ToolLoader/> </div>
  <section data-testid="about-tool" aria-labelledby="about-heading"
           class="mt-16 w-full max-w-3xl border-t border-border pt-8">
    <h2 id="about-heading" class="text-[14px] leading-[1.4] font-semibold text-muted-foreground">About this tool</h2>
    <div class="mt-4">
      <details data-testid="{slug}-worked-example" class="group"> ... </details>
      <details data-testid="{slug}-faq" class="group"> ... </details>
    </div>
  </section>
</main>
```

Rules:
- Tool first: the About section is the LAST element in `<main>`. Nothing about the About area may push the tool down (INFO-01).
- Both `<details>` are closed on load: NO `open` attribute, ever, in server HTML (INFO-02). Content stays in the server HTML (native `<details>` keeps children in DOM).
- No client JS for the disclosure. No `useState`, no `"use client"` in `ToolAbout`.
- The `<h2>` is a real h2 (outline: h1 tool name, h2 About). Summaries are not headings.
- No page keeps its own JSON-LD object/script; `FaqJsonLd` renders exactly one script per page, built from the same `faqItems` array that renders the visible FAQ (INFO-03, INFO-05). Keep `.replace(/</g, "\\u003c")`.

### `<summary>` anatomy (D-05, D-07, D-08)

```
<summary class="flex min-h-11 cursor-pointer list-none items-center gap-2 rounded-lg py-2 text-[16px] leading-[1.5] font-semibold text-muted-foreground transition-colors outline-none select-none hover:text-foreground focus-visible:ring-3 focus-visible:ring-ring/50 [&::-webkit-details-marker]:hidden">
  <ChevronRight aria-hidden="true" class="size-4 shrink-0 transition-transform group-open:rotate-90 motion-reduce:transition-none" />
  Worked example
</summary>
```

- Native marker hidden with both `list-none` and `[&::-webkit-details-marker]:hidden` (Safari). The chevron is the only indicator; identical in all browsers.
- Chevron: lucide `ChevronRight`, `size-4` (16px), inherits text color, rotates 90deg when `[open]` via `group-open:rotate-90`. Transition is transform-only, 150ms default; disabled under `prefers-reduced-motion` (`motion-reduce:transition-none`).
- Focus ring: Button's focus classes, i.e. `outline-none focus-visible:ring-3 focus-visible:ring-ring/50`, with `rounded-lg`. Ring must be visible against both themes; do not clip it (`overflow-hidden` forbidden on `<details>` and its parent).
- Cursor: pointer. Hover: label + chevron go from `muted-foreground` to `foreground` (chevron inherits via currentColor).
- Mouse click, Enter, and Space toggle natively. No custom key handlers on `<summary>`.
- Do not use `aria-expanded`/`role` overrides; native semantics are the contract.

### Open content (D-03, D-06)

- Container: `pl-6 pb-4` (24px indent aligns text under the label; 16px bottom padding), `pt-2`.
- Worked example body = existing per-tool markup preserved (UUID v4/v7 rows, Subnet, DNS, MAC, Hash blocks). Remove only the per-page `<section className="mt-12">` wrapper and the 20px "Worked example"/"FAQ" `<h2>` (the summary replaces them). Keep inner testids (`{slug}-worked-example-*`).
- FAQ body = flat list: `<div class="space-y-6">` of items. Each item: `<div data-testid="{slug}-faq-item"><p>question</p><p>answer</p></div>`. Keep EXACTLY two `<p>` children per item and no nesting — existing `*-seo.spec.ts` read `locator("p").nth(0/1)` for question/answer.
- Individual questions are NOT `<details>` (D-06).
- Content is selectable/copyable; no buttons inside the About area.

### Keyboard (INFO-04)

- Tab order: tool controls, then summary 1, summary 2 (DOM order; no `tabindex`).
- Enter / Space on a focused `<summary>` toggles only that disclosure. `isInteractiveTarget` in `lib/hooks/useKeyboardShortcut.ts` must include `summary` in its selector (`'button, [role="button"], [role="radio"], a[href], summary'`), so no tool's global Enter shortcut (UUID regenerate, DNS lookup, etc.) fires. Unit test + e2e per CONTEXT.
- Do not promise find-in-page into closed `<details>` anywhere in copy.

### Responsive

- 320px: About area has no horizontal overflow; summary text may wrap (never truncated); long mono strings use `break-all` (existing); Config code pane scrolls horizontally inside its own container.
- >= 768px: identical layout; width capped by `max-w-3xl`.
- Dark mode: inherits tokens; no per-component dark overrides except existing Config `dark:` token classes.

## Config Worked Example (CFG-01, D-09..D-12)

Layout inside the Worked example `<details>` for `/tools/config`:

1. Caption (14px/600/foreground): `Cisco IOS snippet, highlighted (documentation addresses only, RFC 5737)`
2. Code pane — mirrors the tool's preview pane look:
   - wrapper: `data-testid="config-worked-example-preview" role="region" aria-label="Highlighted example configuration" tabIndex={0}` + `mt-2 max-w-full overflow-x-auto rounded-lg border border-border bg-secondary focus-visible:ring-3 focus-visible:ring-ring/50 outline-none`
   - `<pre class="min-w-full w-max p-4 font-mono text-[14px] leading-[1.5]">` containing token `<span>`s with `className={TOKEN_CLASSES[token.kind]}` and `data-token={token.kind}`, lines joined with `"\n"`, exactly as `ConfigTool` does.
   - Output only; no separate plain-input block, no buttons (D-10, D-12).
3. One sentence (16px/400/muted, `mt-4` = 16px, md step of the declared scale), D-12: `Copy for email keeps these colors and the monospace formatting when you paste into email or documents. Copy plain text gives the raw configuration.`

Sample text (D-09, verbatim; render via `highlightConfig(SAMPLE, "cisco")` in the server component; never hand-write spans unless the server-safety fallback is triggered):

```
hostname edge-rtr-01
!
interface GigabitEthernet0/1
 description Uplink to ISP
 ip address 192.0.2.1 255.255.255.252
!
ip access-list extended MGMT-IN
 remark allow SSH from docs net
 permit tcp 198.51.100.0 0.0.0.255 any eq 22
!
ip route 0.0.0.0 0.0.0.0 192.0.2.2
```

Only RFC 5737 ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) and the unspecified `0.0.0.0` default route; no passwords, keys, SNMP communities. The planner should verify (unit test) that the sample exercises every token kind reachable by the cisco tokenizer (comment, command, keyword, interface, address, number, string); if a kind is not reached, adjust within the D-09 ~11-line baseline and tell the user.

Implementation note (mandatory): `ConfigTool.tsx` is a `"use client"` module, so its non-component `TOKEN_CLASSES` export cannot be consumed by a Server Component. Move `TOKEN_CLASSES` (and `MONOCHROME_TOKEN_CLASSES`) to a plain module (`lib/config/token-classes.ts`, no `"use client"`) and import it from both `ConfigTool.tsx` and the server example. Values unchanged, so the tool and example cannot drift. Fallback (static pre-highlighted sample) only if `highlightConfig` proves not server-safe (expected safe: pure TS, no browser APIs).

Layout of `/tools/config` page: keep `max-w-6xl` main and the existing intro `<p>` under the h1; `ToolAbout` is added after the tool block with `w-full max-w-3xl` (left-aligned, no `mx-auto`).

### Config FAQ (CFG-02, D-13) — proposed final wording

Location: `app/tools/config/faq-data.ts` exporting `faqItems: FaqItem[]` (same `{question, answer}` shape as other tools). Answers are plain strings (they also become JSON-LD `text`). Count: 4 (D-13); Claude's discretion allows up to 2 more (max 6).

1. Q: `Is my configuration uploaded anywhere?`
   A: `No. Highlighting and copying run entirely in your browser tab. Your configuration is never uploaded, stored or sent to a server, and it is gone when you close or reload the page. Even so, it is good practice to remove passwords, keys and SNMP community strings before you paste a configuration into any tool or share it with others.`

2. Q: `How do I paste highlighted config into Outlook, Word or Google Docs?`
   A: `Click Copy for email, then paste. Outlook, Word and Google Docs keep the colors and the monospace font. Use Copy plain text when you need the raw configuration, for example to paste back into a terminal or a ticket system that strips formatting. If your browser blocks rich copying, the tool says so and copies plain text instead.`

3. Q: `Which vendors and syntaxes are supported?`
   A: `The Cisco profile is built for IOS, IOS-XE and IOS-XR style configuration: commands, interfaces, IP addresses, numbers, descriptions and comments are colored. Other vendors that use a similar line-based syntax will often highlight reasonably well, but they are not specifically supported. Choose Plain text to copy any configuration as monospace text with no coloring.`

4. Q: `What is the Monochrome option for?`
   A: `Monochrome removes the colors but keeps the monospace font, bold commands and italic comments. Use it for printing, grayscale documents, or any place where colored text is hard to read or not allowed. It applies to both the preview and the rich copy.`

Accuracy requirements for the planner/executor: verify claim 3 and 4 against `lib/config/highlight.ts` (`INLINE_EMPHASIS`, `MONOCHROME_TOKEN_CLASSES`) and `lib/config/clipboard.ts` (rich-copy fallback message `Copied as plain text`) while writing; adjust wording to the shipped behavior, never the reverse. "Gone when you close or reload" must be confirmed (ConfigTool state is in-memory `useState`; the footer note says "stays in this browser tab and is never uploaded or saved").
