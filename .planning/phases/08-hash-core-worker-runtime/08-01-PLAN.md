## Why the tracer is one task (file-count justification, 14 files)

The checker's warn threshold is 10 files per task. The tracer stays one task on purpose, for these reasons:
- Every candidate split breaks the tracer's end-to-end verify. A "runtime chain" task (lib/hash only) has no page and so no production-Worker proof; it could only be checked in Node, and the one new risk in this phase (a Turbopack module Worker in a pinned Next 16.2.11 production build, 08-RESEARCH Pattern 4) would move into a second task. Moving the dependency install ahead of the tracer breaks the tracer-first rule, and the tracer cannot run without it.
- Nothing can come off the path. FACTORIES is a typed `Record<AlgorithmId, ...>`, so crc32.ts and all 10 engine rows are required to compile. source.ts, job.ts, worker-core.ts, hash.worker.ts, and client.ts each carry one hop of the single message path. The harness page, its client island, the prod Playwright config, and the spec are the far end of the stack.
- The files are small and copied from verified references. The lib/hash runtime references in 08-RESEARCH (lines 286-551) were typechecked, linted, built, and run in Chrome during research. The harness and the Playwright config are under 40 lines each.
