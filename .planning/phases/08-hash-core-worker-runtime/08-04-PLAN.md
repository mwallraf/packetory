<objective>
Expansion slice on the proven tracer: make the two properties that keep the engine out of initial page JS mechanically enforced in CI - only `engine.ts` may import `@noble/hashes` (ESLint) and only the worker chain may reach `engine.ts` (source-walk test) - and prove the test-only harness can never leak into a default build.

After this plan, a future Phase 9/10 change that imports the engine, job, or worker-core from UI code (which would silently ship ~19 KB of hashing code to every visitor) fails lint or `npm test`, and the `/hash-smoke` route is proven 404 without its build flag.

Purpose: HASH-04 ("the hash engine ... is not part of the initial page JS") as a durable guard rather than a one-time e2e observation; the HASH-04 safety prohibition for the harness.
Output: an ESLint flat-config block, `lib/hash/boundaries.test.ts`, `app/hash-smoke/page.test.tsx`, `tests/e2e/hash-smoke-gate.spec.ts`.
</objective>
