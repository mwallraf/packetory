<objective>
Deliver the DNS Lookup walking skeleton: a complete end-to-end vertical slice where a user loads
`/tools/dns` and immediately sees `cloudflare.com` A records resolved over DNS-over-HTTPS, can switch
among all 6 record types, type/paste/Enter/Refresh to look up any domain, see the resolver used and
lookup duration, copy any value, and share the state via a bookmarkable `?name=&type=` URL — all with
race-safe request cancellation and CLS-free loading states.

Purpose: This is the first Packetory tool with an external async dependency. This plan establishes the
debounce + AbortController-race-safety + primary→fallback resolver orchestration from scratch (no prior
codebase precedent), plus the framework-agnostic `lib/dns/` core that later plans and any future API
route reuse. It follows the exact walking-skeleton-in-wave-1 shape proven by Phase 3's `03-01`.

Output: `lib/dns/` core (types, validate, query, resolve, parse) with unit tests; the
Server-shell/Client-island page (`page.tsx`, `DnsToolLoader.tsx`, `DnsTool.tsx`); the registry flip;
and a happy-path E2E test.

Scope boundary: the FULL 5-state QUAL-08 error matrix (NXDOMAIN vs empty-NOERROR distinct cards,
rate-limited/resolver-unavailable Try-again cards) is `04-02`; SEO metadata + worked example + FAQ +
resolver disclosure is `04-03`. This plan renders success + loading + a minimal generic
invalid-input/failure fallback so the skeleton is coherent end-to-end without those refinements.
</objective>

<assumption_delta_decision>
Detector `assumption-delta scan 4` fired (`detected: true`) on the singular→plural signal "resolver
(primary or fallback)". Decision: **add-alongside**. There is NO pre-existing "resolver" concept
anywhere in the codebase (this is the first tool with an external resolver), so there is no prior
singular assumption to demote/promote. The resolver abstraction is therefore born pluralized from day
one: `resolveWithFallback` returns `resolverUsed: "primary" | "fallback"` as a first-class field, and
no code path ever assumes a single implicit resolver. No existing symbol is renamed or migrated.
</assumption_delta_decision>

<assumptions>
Planner resolutions to RESEARCH open questions / flagged assumptions (recorded so they are not silently
decided by the executor):
- **A1 (SERVFAIL / UI-SPEC unresolved row):** RCODE 2 (SERVFAIL) from the primary resolver IS treated
  as a genuine failure that triggers fallback to Google. SERVFAIL never surfaces as its own distinct UI
  state — a successful fallback renders normally, a failed fallback renders as resolver-unavailable
  (04-02). This resolves the UI-SPEC "⚠ unresolved" SERVFAIL row (option a).
- **Open Question 1 (debounce delay):** fixed constant `DEBOUNCE_MS = 700` (midpoint of the locked
  600–800ms window), not runtime-configurable — matches the codebase's `DEFAULT_CIDR`/`DEFAULT_REVERT_MS`
  one-true-value style.
- **Open Question 2 (duration scope):** total wall-clock from trigger to final answer (a single
  `performance.now()` bracket in `runLookup`), including any failed primary attempt; displayed as an
  integer ms.
- **A2 (URL sync timing):** `?name=&type=` syncs only when a lookup actually commits (debounce fires or
  an immediate trigger runs), never on every keystroke — so a bookmark never captures a mid-typing
  fragment. This intentionally differs from Subnet's every-valid-keystroke sync (Subnet compute is
  synchronous/local).
- **A3 (per-resolver timeout):** `RESOLVER_TIMEOUT_MS = 5000` per resolver (via `AbortController` +
  `setTimeout`) before treating a resolver as failed and failing over / surfacing resolver-unavailable.
</assumptions>
