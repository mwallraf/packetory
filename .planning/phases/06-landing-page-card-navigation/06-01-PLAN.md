<objective>
Make active tool cards in the landing-page grid clickable across their whole surface, keyboard-operable, and visually affordant — reaching parity with the nav menu — while keeping status:"planned" cards inert. Implements LP-01 via the stretched-link pattern (D-01/D-02) with a full-card hover/focus-visible ring (D-03/D-04), and locks the behavior with a component unit test plus updated E2E coverage.

Purpose: Today the landing grid is a visual-only listing whose cards render no clickable anchor; the nav menu already links correctly. This closes that gap so a visitor can get to a tool in one click from the grid.
Output: Modified components/ToolCard.tsx, new components/ToolCard.test.tsx, updated tests/e2e/home.spec.ts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser user → client-side router | User clicks/keys a card; `next/link` performs a same-origin client-side navigation to a registry-derived path |
| tool registry (build-time) → rendered href | The static `tools/registry.ts` slug is interpolated into the card link `href` at build time (not user input) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | ToolCard `<Link href={/tools/${tool.slug}}>` | low | mitigate | `href` is always prefixed with the literal `/tools/` and the slug comes from build-time-static `tools/registry.ts` (no user input), so it cannot be coerced into an absolute/external URL or a `javascript:` scheme; navigation stays same-origin and relative. |
| T-06-02 | Information Disclosure | card click navigation | low | accept | Card clicks are non-destructive same-origin navigations; per the project privacy NFR no click tracking/analytics is added, so no PII or sensitive query param is emitted. Accepted: no sensitive data crosses a trust boundary. |
| T-06-03 | Elevation of Privilege | stretched-link `after:inset-0` overlay | low | mitigate | The overlay is anchored to its own `relative` Card ancestor (`inset-0`), never overlaps sibling cards, and the header/theme-toggle live in a separate sticky stacking context — so it cannot hijack clicks intended for other interactive controls. |

**Package legitimacy:** No npm/pip/cargo install tasks in this plan (only `next/link`, already a project dependency), so the Package Legitimacy Gate and a `T-06-SC` supply-chain threat are not applicable. ASVS L1; block-on-high — all threats are low severity, so none block execution.
</threat_model>
