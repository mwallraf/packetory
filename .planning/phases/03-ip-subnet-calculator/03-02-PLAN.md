## Phase Goal (MVP user story)

**As a** network engineer, **I want to** enter an IPv4 or IPv6 CIDR and instantly see its full, mathematically-correct subnet breakdown with every field copyable and the result reflected in a shareable URL, **so that** I can get my subnet answer in seconds and hand a teammate a link that reproduces it exactly.

## MVP Slice — what a user can do after this plan

Before: the IPv4 grid shows 7 fields but no reverse-DNS zone. After: the IPv4 grid is complete — a user also sees and copies the `in-addr.arpa` reverse-DNS zone, with a clear note whenever the prefix isn't octet-aligned. (The RFC-5952 and `ip6.arpa` formatters built here light up in the IPv6 plans.)

## Surfaced assumption (not silently dropped)

**A1 / UI-SPEC unresolved row — reverse-DNS display for non-aligned prefixes.** RESEARCH Open Question 1 and the UI-SPEC "reverse-dns-note" row are UNRESOLVED: whether the product wants the truncated-nearest-boundary display (this plan's default, drafted in the UI-SPEC Copywriting Contract) or a full RFC 2317 classless-delegation name for IPv4 was never put to the user. This plan implements the truncated-boundary-plus-note approach as an EXPLICIT PLANNER ASSUMPTION, consistent with D-04's "always a real value plus a short note, never N/A" precedent. It is additive and can be refined to RFC 2317 later without breaking other fields. Flag it in the SUMMARY so verify-phase surfaces it for the developer.
