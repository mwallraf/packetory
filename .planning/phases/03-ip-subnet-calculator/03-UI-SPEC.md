**New shadcn components required this phase:** none. Reused unchanged from Phase 1/2: `Input`, `Label` (CIDR field), `Badge` (IPv4/IPv6 family indicator), `Tooltip` (optional field-name clarifications, e.g. "wildcard mask"), `Separator` (between IPv4/IPv6 grid and the subdivision section), plus `lib/hooks/useCopyToClipboard.ts` and `lib/hooks/useKeyboardShortcut.ts`. Per-field copy buttons and subdivision-suggestion buttons both reuse the raw-`<button>` + Tailwind-utility pattern already established in `UuidTool.tsx` (accent-tinted pill, 44×44 min hit area) — not the `components/ui/button.tsx` primitive, for consistency with Phase 2's precedent.

**Page structure (informs Spacing/Typography roles below):**
1. `h1` "IP Subnet Calculator" (Display)
2. CIDR `Input` + family `Badge` (auto-detected IPv4/IPv6, SUBNET-01) + inline validation slot (SUBNET-03)
3. Parsed-CIDR summary value (Heading-size mono "hero," e.g. `192.168.1.0/24`) with its own copy button — the page's single most-visible derived value, filling the same visual role UUID's single-value hero did in Phase 2
4. One field grid — IPv4 (8 fields, SUBNET-04) or IPv6 (6 fields, SUBNET-05) — never both, chosen by the same auto-detect as step 2
5. IPv6-only: "Subdivide this block" section with 0–3 clickable prefix-length pills (D-05/D-06), hidden entirely when empty
6. Worked example section (static, mirrors Phase 2's shape)
7. FAQ section (static, mirrors Phase 2's shape)

## Spacing Scale

Declared values (must be multiples of 4) — inherited unchanged from Phase 1:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (field label ↔ value ↔ copy button) |
| md | 16px | Default element spacing; field-grid gap (`grid gap-4`) |
| lg | 24px | Section padding (worked-example, FAQ blocks) |
| xl | 32px | Layout gaps (between CIDR input row, hero summary, and field grid) |
| 2xl | 48px | Major section breaks (result section → worked example → FAQ) |
| 3xl | 64px | Page-level spacing (top/bottom page padding, matches `app/page.tsx`'s `py-12`) |

Exceptions:
- Icon-only interactive controls (per-field copy buttons, subdivision pills) keep the Phase 1 minimum 44×44px hit area via padding around a smaller visual icon/text (16–20px equivalent), never by breaking the 4px grid — identical rule to Phase 2.
- Field grid uses `grid-cols-1 sm:grid-cols-2 gap-4` (16px gap, already on-grid) — one column below the `sm` breakpoint (640px) so 320px viewports never horizontal-scroll or clip a field row; documented here only so the executor doesn't invent an arbitrary breakpoint.

## Typography

Inherited unchanged from Phase 1/2 — same 4 declared sizes/weights, reused for this phase's content:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 600 (semibold) | 1.4 |
| Body | 16px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 32px | 600 (semibold) | 1.2 |

Phase 3 role assignments:
- **Display** — page `h1` only ("IP Subnet Calculator"), one per page.
- **Heading** — the parsed-CIDR summary "hero" value (e.g. `192.168.1.0/24`); section headings ("IPv4 details" / "IPv6 details", "Subdivide this block", "Worked example", "FAQ").
- **Body** — every field value in the IPv4/IPv6 grids (network address, broadcast, masks, binary, reverse-DNS zone, etc.); boundary-case notes (D-04); reverse-DNS non-aligned-prefix notes; worked-example prose; FAQ answers; page intro paragraph.
- **Label** — CIDR input label, field-name labels in the grid ("Network address", "Wildcard mask", etc.), family-badge text ("IPv4"/"IPv6"), subdivision-pill text ("/56", "/64"), FAQ question text, copy-button `aria-label`/visible captions.

**Monospace override** (same rule extended from Phase 1/2's IP/UUID values): Geist Mono replaces Geist Sans, at the same size/weight as the role it appears in, for every address/mask/binary/reverse-DNS-zone value on this page —
- Parsed-CIDR hero value: Heading size/weight (20px/600) in Geist Mono.
- Every IPv4/IPv6 grid field value: Body size/weight (16px/400) in Geist Mono.
- Subdivision pill labels: Label size/weight (14px/600) in Geist Mono (they're literal CIDR prefix fragments, e.g. `/56`).

## Color

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `#FFFFFF` white | `#020617` slate-950 | Page background |
| Secondary (30%) | `#F1F5F9` slate-100 | `#0F172A` slate-900 | Parsed-CIDR hero row, IPv4/IPv6 field-grid card surface, worked-example/FAQ surfaces |
| Accent (10%) | `#0891B2` cyan-600 | `#22D3EE` cyan-400 | See reserved list below |
| Destructive | `#DC2626` red-600 | `#EF4444` red-500 | Reserved — no destructive actions exist in Phase 3 |

Accent reserved for (explicit list — never "all interactive elements"):
- Copy-button icon default/hover/active state + "Copied!" flash — every per-field copy action across the IPv4 grid (8), IPv6 grid (6), and the parsed-CIDR hero value's own copy button
- Subdivision-suggestion pills (`/56`, `/64`, etc.) — the page's core interactive/repeatable action for this phase (D-05), the direct analogue of Phase 2's Regenerate button
- Keyboard focus ring (all interactive elements — inherited global rule)

Deliberately kept neutral (outline/border/muted styling, not accent), to avoid accent overuse:
- CIDR `Input` border/focus-within state — uses the shared `Input` primitive's own default focus styling, not a page-level accent override
- Family `Badge` (IPv4/IPv6 indicator) — neutral/outline badge, consistent with Phase 2's guidance to reserve accent for specific action elements only
- Field-value text itself, boundary-case notes, reverse-DNS non-aligned-prefix notes — plain `text-foreground`/`text-muted-foreground`, never accent-colored (notes are informational, not actionable)
- Worked-example card border, FAQ section styling

Destructive is reserved and unused this phase — consistent with Phase 1/2: editing the CIDR input or clicking a subdivision suggestion instantly replaces the displayed result and URL (D-06), nothing is destroyed or persisted to lose, so no confirmation pattern is needed.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Copy" — icon-only button (`Copy`/`Check` swap, "Copied!" `aria-label`) next to every output field (SUBNET-06) and next to the parsed-CIDR hero value; no single dominant action beyond copy, since the result computes live with zero required input (SUBNET-02) |
| Secondary CTA — subdivision (IPv6 only) | Pill button labeled with the literal prefix (e.g. `/56`), `aria-label="Split into /56"` — clicking replaces the top-level CIDR input and URL with the first available block at that prefix length (D-05/D-06); the whole "Subdivide this block" section is omitted (not shown empty) when the current prefix is already ≥ `/64` or the family is IPv4 |
| Empty state | Not applicable — page always pre-fills and calculates the D-02 private-range default (`192.168.1.0/24`, or the brief's `10.20.0.0/20`) on load; SUBNET-02 guarantees a populated result at all times, same reasoning as Phase 2's always-generated UUID |
| Error state — invalid CIDR (typed) | "Enter a valid IPv4 or IPv6 CIDR, like 192.168.1.0/24 or 2001:db8::/32." — shown inline below the input via `aria-invalid` + `aria-describedby`, never a popup/reload (SUBNET-03); the last valid result stays visible and unchanged while this message shows |
| Error state — invalid `?cidr=` URL param on load | "The shared link's CIDR (\"{rawParam}\") isn't valid — showing the default example instead." — same inline slot as above, shown once at mount when the URL param fails validation; falls back to the D-02 default per RESEARCH.md Pattern 1 |
| Error state — copy failure | "Couldn't copy — select the text and copy manually." — identical wording to Phase 1/2's `useCopyToClipboard` pattern, reused verbatim; independent per-field confirmation state (no cross-field bleed) |
| Boundary-case note — `/31` (IPv4, D-04) | "Both addresses are usable — /31 point-to-point links have no broadcast address (RFC 3021)." |
| Boundary-case note — `/32` (IPv4, D-04) | "Single address — network, broadcast, first, and last host are all the same address." |
| Boundary-case note — `/127` (IPv6, D-04) | "Both addresses are usable — /127 point-to-point links follow the same no-broadcast convention as IPv4 /31." |
| Boundary-case note — `/128` (IPv6, D-04) | "Single address — first and last address are the same address." |
| Reverse-DNS non-aligned-prefix note **[ASSUMPTION — RESEARCH.md Open Question 1, not a user-confirmed decision]** | "Zone shown to the nearest fully covered {octet/nibble} boundary — /{prefix} doesn't align exactly." — drafted per RESEARCH.md's recommended truncated-boundary display; a full RFC 2317 classless-delegation name is NOT built this phase |
| Destructive confirmation | None — no destructive actions exist; editing the CIDR input or clicking a subdivision suggestion instantly replaces the displayed result and URL (D-06), fully reversible by editing again or pressing `Esc` to restore the default example |

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | cidr-input + result (page-level) | ✅ covered | SUBNET-02 guarantees the D-02 private-range default is pre-filled and computed synchronously on load — no reachable "no result" state, same reasoning as Phase 2's always-generated UUID hero. |
| loading | cidr-input + result (page-level) | ✅ covered | Computation is synchronous BigInt math with no network call (D-03) — the `ssr:false` client loader (mirrors `UuidToolLoader`) shows a fixed-height skeleton only until client mount; no spinner exists for the math itself. |
| error | cidr-input (interactive-control) | ✅ covered | Invalid typed input or an invalid `?cidr=` URL param both render the inline messages in Copywriting Contract — never a popup/reload (SUBNET-03), and the last valid result stays visible while the message shows. |
| populated | ipv4-field-grid / ipv6-field-grid (list-collection) | ✅ covered | Exactly one grid renders per calculation, chosen by SUBNET-01's family auto-detect — never both, never neither. |
| zero-one-many | ipv4-field-grid vs ipv6-field-grid (list-collection) | ✅ covered | Family auto-detect (SUBNET-01) is one deterministic branch: IPv4 renders the 8-field grid (SUBNET-04), IPv6 renders the 6-field grid + subdivisions (SUBNET-05) — same shape as Phase 2's hero-vs-list branch. |
| partial | ipv4-field-grid / ipv6-field-grid | ✅ covered | Every field is computed atomically from the same parsed CIDR in one `lib/subnet/` pass — no reachable "half-computed" grid; a parse failure short-circuits to the error state instead of a partially populated grid. |
| overflow | ipv4-field-grid / ipv6-field-grid | ✅ covered | Fixed field count (8 IPv4 / 6 IPv6) with a responsive `grid-cols-1 sm:grid-cols-2` layout — 320px viewports stack to one column, no horizontal scroll/clipping; no unbounded list exists here (contrast with UUID's variable-length batch). |
| long-text | ipv4/ipv6 grid values (reverse-DNS zone, expanded IPv6 notation) | 🧪 backstop | Reverse-DNS zone strings (up to ~64 chars for a nibble-reversed IPv6 `/64`) and expanded IPv6 notation (39 chars) must wrap, never clip, at 320px — same backstop pattern as Phase 2's UUID value. Needs a visual test at 320px for both families. |
| zero-one-many | subdivision-options (list-collection, IPv6 only) | ✅ covered | RESEARCH's recommended fixed next-step list (Open Q2) yields 0–3 options (e.g. `/32` input → `/48`,`/56`,`/64`; `/56` input → `/64` only; `/64`+ input → none). The "none" case hides the whole section rather than rendering an empty box — one deterministic list-length branch, not per-count special casing. |
| empty | subdivision-options (list-collection) | ✅ covered | See row above — input already ≥ `/64`, or IPv4 family (subdivision doesn't apply, SUBNET-05 is IPv6-only), is an explicit hidden-section state, not a blank/placeholder list. |
| error | copy-actions (interactive-control, repeated across all fields + hero) | ✅ covered | Reuses `lib/hooks/useCopyToClipboard.ts` unchanged (Phase 1/2 pattern) — a rejected clipboard write shows the same inline "Couldn't copy" message per field, independent confirmation state per field/instance (no cross-field bleed). |
| unresolved | reverse-dns-note for non-octet/non-nibble-aligned prefixes | ⚠ unresolved | RESEARCH.md Open Question 1: whether the truncated-boundary display (this spec's default, drafted in Copywriting Contract) or a full RFC 2317 classless-delegation name is wanted was never put to the user — planner/executor must treat the truncated-boundary + note approach as an explicit assumption, not a locked decision. |
| overflow / long-text | worked-example, faq (static-content) | ✅ covered | Same as Phase 1/2 — static build-time copy, standard prose wrap, no variable-length/user-generated input risk. |
