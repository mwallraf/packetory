# Phase 14 — UI Design Contract

> Visual and interaction contract for finishing and launching `/tools/password`: Passphrase mode, the strength panel, registry/nav/landing entry, final metadata and the About/FAQ area. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `14-CONTEXT.md` (D-01..D-20, locked, auto-accepted), `ROADMAP.md` Phase 14, `REQUIREMENTS.md` (PHR-01..04, STR-01..04, PREG-01..03), `13-UI-SPEC.md` (the direct predecessor; every token, type size, spacing value, focus style and live-region rule carries forward unless this file overrides it), `13-UI-REVIEW.md` + `13-REVIEW-DISPOSITION.md` (post-review baseline: UI-2, UI-3, IN-07), `10-UI-SPEC.md` + `components/ToolAbout.tsx` (About conventions), and a code scan of `app/tools/password/*`, `app/tools/config/{page,ConfigExample}.tsx`, `app/tools/hash/OutputToolbar.tsx`, `components/ui/{toggle-group,toggle}.tsx`, `components/SiteHeader.tsx`, `tools/registry.ts`, `app/globals.css` and `lib/password/*`.

**This file extends 13-UI-SPEC.md.** Anything not restated here (hero markup, batch rows, Length/Character sets/Symbol set/Look-alikes controls, input guard attributes, `<kbd>` styling, the fail-closed crypto error, URL writing) stays exactly as 13-UI-SPEC defines it, with the post-review baseline below applied.

**Post-review baseline carried forward (supersedes 13-UI-SPEC where they differ):**
- Hero **Copy** and **Copy all** are a filled accent pill: `bg-[#0e7490] text-white hover:bg-[#155e75] dark:bg-primary dark:text-primary-foreground dark:hover:bg-primary/90` (5.36:1 light, 11.16:1 dark). This replaces 13-UI-SPEC's ghost `text-primary` Copy (UI-2, IN-07).
- Batch **row copy** is icon-only in both states: `h-11 w-11 px-2`, `Copy` size-5 at rest, `Check` size-5 plus `sr-only` "Copied!" when confirmed, and the row does not wrap (UI-3, IN-08).
- The row uses `<li class="py-1">` with an inner non-wrapping flex row, and the copy-error line sits below that row with `mt-2`.

No new CSS variables, fonts or dependencies. One new Tailwind palette pair appears on this page: `emerald-700/emerald-300` for the Strong and Very strong meter segments. `globals.css` has no success token (checked: only background, foreground, primary, secondary, muted, border, input, ring and destructive exist).

## Color

No new CSS variables. Contrast was computed with the WCAG 2.x formula on 2026-11-11.

| Role | Value (light / dark) | Usage in this phase |
|------|----------------------|---------------------|
| Dominant (60%) | `--background` `#ffffff` / `#020617` | Page, the strength panel surface, the Options section, the wordlist error panel, the About area |
| Secondary (30%) | `--secondary` `#f1f5f9` / `#0f172a` | Hero and batch surfaces (both modes), the loading placeholder, skeleton blocks, `<kbd>`, the worked-example placeholder block |
| Accent (10%) | `--primary` `#0891b2` / `#22d3ee`, plus the darker light-mode shade `#0e7490` (cyan-700) | See the reserved list below |
| Destructive | `--destructive` `#dc2626` / `#ef4444` | Fail-closed errors (crypto and wordlist), and the Weak meter segment |
| Muted text | `--muted-foreground` `#64748b` / `#94a3b8` | Only on `bg-background`: hints, pool line, assumption, credit line, intro, slider scale, shortcut line (4.76:1 light, 7.87:1 dark) |
| Border | `--border` `#e2e8f0` / `#1e293b` | Strength panel border, empty meter segments, toggle outlines (`border-input`, same value) |

Accent reserved for (explicit list; anything not listed must not use the accent):
1. Copy controls, as in the post-review baseline: the filled hero Copy and Copy all, and the `text-primary` icon of the batch row copy. This applies in both modes.
2. The checked track of every `Switch` (now also Capitalize words and Append a number).
3. The thumb and fill of both range inputs (`accent-primary`: Length and Word count).
4. The keyboard focus ring (`ring-ring/50`) on every control, including toggle items, links and the Retry button.
5. **New:** the selected item of the three toggle groups (Mode, Separator, Attack scenario): `bg-primary/10` with `text-cyan-700` / `dark:text-primary`.

The accent is NOT used for Regenerate or Retry (neutral outline), the strength meter, the strength label, any link (credit line, About links), any hint or body text, or the passphrase characters.

### Strength meter colors (D-06)

| Level | Filled segments | Segment class | vs `bg-background` (light / dark) |
|-------|-----------------|---------------|-----------------------------------|
| Weak (< 40 bits) | 1 of 4 | `bg-destructive` | 4.83:1 / 5.36:1 |
| Fair (40–74) | 2 of 4 | `bg-amber-700 dark:bg-amber-300` | 5.02:1 / 13.99:1 |
| Strong (75–99) | 3 of 4 | `bg-emerald-700 dark:bg-emerald-300` | 5.48:1 / 13.23:1 |
| Very strong (≥ 100) | 4 of 4 | `bg-emerald-700 dark:bg-emerald-300` | 5.48:1 / 13.23:1 |
| Unfilled | — | `bg-border` | decorative |

- Filled segments clear the 3:1 non-text minimum in both themes. The segment strip is `aria-hidden`. The level is always carried by the visible text label, so the meaning never depends on color or on the unfilled segments (WCAG 1.4.1, 1.4.11).
- Strong and Very strong share a color. They differ in segment count and label text.
- The strength label text is `text-foreground`, not tinted. Color appears only on the segments.

### Contrast rules (binding, carried from 13 and extended)
- Muted and destructive text never sit on `bg-secondary`. The strength panel, the wordlist error panel and the credit line are all on `bg-background`.
- The structural placeholder `word-word-word-word-word-word` inside the worked example sits on `bg-secondary` and uses `text-foreground` (16.30:1).
- Links use `text-foreground underline underline-offset-4`, never the accent. They are distinguishable from the surrounding muted text by both the underline and the contrast step.

### Passphrase output coloring (D-20e)
`ColoredPassword` is reused unchanged: letters `text-foreground`, digits `text-sky-700 dark:text-sky-300`, symbols `text-amber-700 dark:text-amber-300` (13-UI-SPEC contrast table applies). In passphrase mode the `-` `_` `.` separators, and the hyphens inside the 4 hyphenated EFF words, therefore render as symbols, and the appended digit renders as a digit. A space separator is a real space character inside a letter or symbol run, and copying writes the raw string.

## Interaction & Layout Contract

### Visual hierarchy / focal point
1. Primary anchor: the generated value (password or passphrase) in the `bg-secondary` hero, 20px/600 mono, unchanged.
2. The filled accent Copy button directly under it.
3. Regenerate (neutral outline) next to Copy.
4. The strength panel directly under the output, a quiet bordered card on the page background. Only its 8px meter strip carries color.
5. Options (h2) after a 32px gap. Then the About area after 64px, muted and collapsed.

The Mode toggle sits above the hero so the mode is read first (D-01). It is compact (one 44px row), so it does not compete with the hero.

### Page shell (D-12, D-13)

```
<div class="flex flex-1 flex-col bg-background">
  <main class="mx-auto w-full max-w-3xl flex-1 px-4 py-12 sm:px-6 lg:px-8">
    <h1 class="text-[32px] leading-[1.2] font-semibold text-foreground">Password Generator</h1>
    <p data-testid="password-intro" class="mt-4 text-[16px] leading-[1.5] font-normal text-muted-foreground">{intro}</p>
    <div class="mt-8"><PasswordToolLoader /></div>
    <ToolAbout slug="password" faqItems={faqItems}><PasswordExample /></ToolAbout>
  </main>
</div>
```

The page imports only server-safe barrel exports from `@/lib/password`. It never imports the island or the wordlist.

### Island structure

```
<div class="flex flex-col gap-8">
  <div class="flex flex-col gap-4">
    <ModeToggle />                                   ← fixed h-11 row
    <div data-testid="password-output-zone">         ← exactly one of: hero | batch | crypto error | wordlist loading | wordlist error
    <StrengthPanel />                                ← always rendered, in every output state
  </div>
  <PasswordOptionsPanel /> | <PassphraseOptionsPanel />
  <span aria-live="polite" class="sr-only" data-testid="password-status">{fixed phrase}</span>
</div>
```

- The mode row has a fixed 44px height and its captions never change width, so switching modes never moves the output zone's top edge (D-17).
- The strength panel renders even while the wordlist is loading or has failed, and also in the crypto-error state, because it is derived from the settings (D-04, D-06).

### Mode toggle (D-01)

```
<div class="flex flex-wrap items-center gap-x-4 gap-y-2">
  <span id="password-mode-label" class="text-[14px] leading-[1.4] font-semibold text-foreground">Mode</span>
  <ToggleGroup type="single" variant="outline" value={options.mode} aria-labelledby="password-mode-label" data-testid="password-mode">
    <ToggleGroupItem value="password"   data-testid="password-mode-password"   class={TOGGLE_ITEM_CLASS}>Password</ToggleGroupItem>
    <ToggleGroupItem value="passphrase" data-testid="password-mode-passphrase" class={TOGGLE_ITEM_CLASS}>Passphrase</ToggleGroupItem>
  </ToggleGroup>
</div>
```

- It fits on one line at 320px (about 40 + 16 + 96 + 8 + 111 = 271px inside 288px).
- Radix roving focus applies: Tab enters the group once, and the arrow keys move between items. Activating an item goes through `commit()` (normalize, `setOptions`, regenerate, write the URL, reset copy confirmations).
- The first activation of Passphrase starts the wordlist load (see Wordlist states). Later switches are synchronous.
- Enter on a focused item does not regenerate. The global guard already skips buttons and radios.

### Passphrase output

Same hero and batch markup as Password mode, with these differences:
- Value classes: `[overflow-wrap:anywhere]` instead of `break-all`, so lines break at word boundaries first. `-` and space already give natural break points. For `_` and `.`, `ColoredPassword` gets an optional `breakAfter` prop (the separator, passphrase mode only) and renders `<wbr />` after each separator character. A `<wbr>` adds no text to the selection or to the copied string.
- Batch toolbar count: `{n} passphrases`.
- Accessible names: `Copy passphrase` (hero), `Copy passphrase {i}` (row), `Copy all passphrases`. `Copied!` while confirmed, as before.
- Error copy uses the passphrase wording (Copywriting Contract).

### Wordlist states (D-04, D-05)

**Loading** (first passphrase use, a passphrase bookmark mount, or Retry):

```
<div data-testid="password-wordlist-loading" aria-hidden="true"
     class="h-[{P320}px] sm:h-[{Psm}px] animate-pulse rounded-md border border-border bg-secondary motion-reduce:animate-none" />
```

- `{P320}`/`{Psm}` are the measured heights of the default 6-word passphrase hero at 320px and ≥640px, recorded in the SUMMARY. The block holds no text. The live region says `Loading word list`.
- No Copy, Copy all or Regenerate is rendered while loading. Enter and Ctrl/Cmd+C do nothing in this state. Esc resets the options and keeps the load going.

**Error:**

```
<div data-testid="password-wordlist-error"
     class="flex min-h-[{P320}px] sm:min-h-[{Psm}px] flex-col items-start gap-4 rounded-md border border-destructive/30 bg-background p-4">
  <div class="flex items-start gap-2">
    <TriangleAlert aria-hidden="true" class="mt-1 size-4 shrink-0 text-destructive" />
    <div role="alert" class="flex flex-col gap-2">
      <p class="text-[16px] leading-[1.5] font-normal text-destructive">Couldn't load the word list, so no passphrase was generated.</p>
      <p class="text-[14px] leading-[1.4] font-normal text-muted-foreground">Check your connection and try again.</p>
    </div>
  </div>
  <button type="button" data-testid="password-wordlist-retry"
          class="inline-flex h-11 shrink-0 items-center justify-center gap-2 rounded-full border border-border px-4 text-foreground outline-none transition-colors hover:bg-muted focus-visible:ring-[3px] focus-visible:ring-ring/50">
    <RefreshCw aria-hidden="true" class="size-5" /><span class="text-[14px] leading-[1.4] font-semibold">Retry</span>
  </button>
</div>
```

- The min-height matches the loading block, so Loading → Error does not shift the layout.
- No passphrase from any source, no copy controls and no Regenerate are rendered. Retry is the only action. It returns to Loading and calls the loader again.
- Retry is a neutral outline button (the Regenerate style). The accent stays reserved for copy.
- Focus: when the error replaces the loading block, focus is not moved. `role="alert"` announces it. After a successful Retry, the Retry button is removed. Focus then falls back to the document body, which is the standard behavior after DOM removal, and the live region announces the result.

**Ready:** generate and render the hero or batch. A stale load (an old sequence token, the mode no longer passphrase, or changed options) applies nothing.
