# Packetory repository instructions

## Required OpenGSD workflow

Before making any repository edits, load and follow the appropriate OpenGSD skill for the task. Use the workflow even when the request does not name a skill. Bypass it only if the user explicitly asks you to. Read-only questions and inspection can proceed directly.

- `$gsd-fast` for trivial inline edits.
- `$gsd-quick` for small fixes, documentation updates, and other ad hoc changes that need a plan.
- `$gsd-debug` for investigating and fixing bugs.
- `$gsd-execute-phase` for executing a planned phase.
- `$gsd-new-milestone` when starting a new milestone.

Read `.planning/PROJECT.md` for project context and `.planning/STATE.md` for the current milestone and work in progress. The existing workflow rule is also documented in `.claude/CLAUDE.md` under “GSD Workflow Enforcement.”
